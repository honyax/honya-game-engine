Phase 1 / ロードマップ該当行: 「シェーディング(ランバート+フォン)、法線」

今日のゴール

球と床に光が当たる。光源を動かすと陰影が追従し、球には鏡面のハイライトが乗る。フラット / グーロー / フォンの3方式を切り替えて、見た目と負荷の違いを体感する。

Day 8 までは「そこに何色を置くか」を貼り付けていただけだった。今日から光の当たり方を計算するようになり、絵が一気に立体的になる。

事前に読む資料

  • ゲームグラフィックス特論 A-6 陰影付け(1) 基本的な陰影付け方程式 —今日の必読。ランバート反射とフォン反射の式そのもの
  • LearnOpenGL: Basic Lighting —環境光・拡散・鏡面の3成分を図で説明している。実装の流れも近い
  • 西川善司「ゲーム制作者になるための3Dグラフィックス技術 改訂3版」Ch11(トゥーンシェーディング)は本Dayの改造課題に直結する

理論の要点

1. 法線 — 面がどちらを向いているか

光の計算に必要な情報は、突き詰めると面の向きだけ。これを表す長さ1のベクトルが法線(ノーマル)。

法線は「位置」ではなく「向き」なので、平行移動の影響を受けてはいけない。変換するときは W=0 の方向ベクトルとして扱う(Day 5 の要点1)。

csharp
v.Normal = Mat4.TransformDirection(v.Normal, model).Normalized();

ただしこれが正しいのは、モデル行列が回転と一様な拡大縮小しか含まない場合。軸ごとに違う倍率(非一様スケール)を掛けると法線が面に垂直でなくなるので、本来は「逆転置行列」で変換する必要がある。本Dayのデモは一様スケールしか使わないので簡易版で足りる。

法線を頂点ごとに持つことには大きな意味がある。

  • 立方体の角のように「位置は同じでも面の向きが違う」場所は、別の頂点として持つ
  • 球のように滑らかな面では、隣り合う三角形で法線を共有する

後者のおかげで、少ない三角形でも丸く見せられる。これが要点4の話につながる。

2. 光の式 — 3つの成分を足すだけ

色 = アルベド x (環境光 + 光の色 x 拡散) + 光の色 x 鏡面
成分何を表すか見る方向に依存するか
環境光 (ambient)どこからともなく当たる光。他の物体からの照り返しの近似しない(定数)
拡散反射 (diffuse / ランバート)ざらざらした面が光を均等に散らすしない
鏡面反射 (specular / フォン)つるつるした面が鏡のように跳ね返すする

拡散反射は内積1つで決まる。

csharp
float diffuse = MathF.Max(Vec3.Dot(n, toLight), 0.0f);

面の向き N と光の向き L の内積が cosθ になる(Day 5 の要点4)ので、「正面から当たれば明るく、斜めなら暗い」という当たり前の現象がこれだけで表せる。内積が負(光が裏から当たっている)なら 0 にする。

鏡面反射は反射方向と視線の一致度。

csharp
Vec3 reflected = Vec3.Reflect(-toLight, n);
float specular = MathF.Pow(MathF.Max(Vec3.Dot(reflected, toCamera), 0.0f), Shininess);

Shininess 乗するのは、近いときだけ急激に大きくするため。指数が大きいほどハイライトは小さく鋭くなる(つるつるした材質に見える)。

最後に、拡散反射は物の色に染まるが、鏡面反射は染まらない。赤いプラスチックのハイライトが白いのはこのため。式でもそう書き分けている。

なおこのモデルは物理的に正しくない(エネルギー保存を満たしていない)。1970年代に「それらしく見える」ことを目的に作られた経験的なモデルで、物理ベースの正しい式は Day 35 の PBR で扱う。それでも今なお基礎として教えられるのは、各項が何をしているか切り分けやすいから。

3. 3つのシェーディング — 式は同じ、計算する場所が違う

方式どこで計算するか1フレームの計算回数見た目
フラット面ごとに1回三角形の数ポリゴンの境目がはっきり見える
グーロー頂点ごとに1回、内部は色を補間頂点の数滑らかだがハイライトが歪む
フォンピクセルごとに、法線を補間して計算ピクセルの数最も正しい

式は3つとも完全に同じ。 違うのは呼ぶ場所だけ。

グーローは Day 4 の要点7で予告したとおり「頂点で計算して内部は補間」という手抜きで、Day 4 の円盤デモがなぜ滑らかに見えたのかの答えでもある。

グーローの弱点はハイライト。光の当たり方は面の中で急激に変わるのに、頂点でしか計算しないので、頂点と頂点の間にあるはずのハイライトが消えたり、逆に頂点にあるハイライトが三角形の形に引き伸ばされたりする。球を見比べると、フォンでは小さく丸いハイライトが、グーローでは三角形状に歪む。

4. 補間した法線は正規化が要る

csharp
Vec3 n = normal.Normalized();   // シェーダの中で必ずやる

単位ベクトル同士を補間しても、結果は単位ベクトルにならない。球面上の2点を結ぶ直線(弦)の中点は、必ず球の内側に入るため。

正規化を忘れると、法線が短くなるぶん内積が小さくなり、面の中央だけが暗くなるという独特の症状が出る。症状が特徴的なので、見たらここを疑うとよい。

5. 索引(インデックス)で頂点変換を減らす

Day 9 で Mesh クラスを導入した。頂点の配列と、それを三角形に組む索引の配列を持つ。

索引の効果はメモリ節約だけではない。頂点変換の回数が減るほうが本質的。

球(24 x 32分割): 三角形 1536枚 / 頂点 825個
  索引なし … 1536 x 3 = 4608 回の頂点変換
  索引あり … 825 回        → 5.6倍の節約

DrawMesh が「まず全頂点をワールドへ変換 → 索引で三角形を組む」という順序なのはこのため。GPUに頂点バッファとインデックスバッファが別々にあるのも同じ理由。

6. 巻き方向をそろえる(制作中に踏んだバグ)

フラットシェーディングでは、面の法線を3頂点の外積から求める。

csharp
Vec3 faceNormal = Vec3.Cross(v1.Position - v0.Position, v2.Position - v0.Position).Normalized();

この向きは頂点を並べた順序(巻き方向)で決まる。順序が逆だと法線が裏返る。

本Dayの制作中、床と立方体の巻き方向が球と逆になっていて、フラットシェーディングにすると床が真っ黒になるというバグを踏んだ。面法線が下を向いていたため、拡散反射が常に0(環境光のみ)になっていた。

そこで全メッシュを「外から見て反時計回り」にそろえた。検証コードで確認したところ、修正後は立方体12枚・球1536枚・床32枚のすべてで面法線と頂点法線の内積が正(最小 0.999)になった。

これは Day 10 の背面カリングの前提でもある。カリングは巻き方向で表裏を判定するので、ここが不揃いだと「表の面が消える」形で必ず表面化する。今日そろえておくのが正解。

7. 実測 — コストは「ピクセルあたり何をするか」で決まる

オフスクリーンで1フレームを測った実測(Release / 1700枚 / 640x480):

グーロー + テクスチャ9.38 ms
フォン + テクスチャ無9.09 ms
フォン + テクスチャ12.97 ms

読み取れること。

  • テクスチャの読み込みが +4.9 ms、ピクセル単位の光の計算が +4.6 ms。ほぼ同じ重さ
  • フラットとグーローは同じ速さ。どちらも「ピクセルあたりは補間した色を出すだけ」なので当然
  • フォンは +37%。ピクセルごとに正規化(平方根)と Pow が入るのが効いている

改造課題

課題1(易): 光の式をいじって効果を切り分ける

  1. Shininess を 2 / 32 / 256 に変える。ハイライトの大きさはどう変わるか
  2. SpecularStrength を 0 にする。何が消えるか。金属らしさ / プラスチックらしさとの関係は
  3. Ambient を 0 にする。影の部分がどうなるか。なぜ真っ黒だと困るのか
  4. 鏡面反射の色を Color ではなく albedo に掛けてみる。金属っぽく見えないか(実はこれが「金属は鏡面反射も物の色に染まる」という PBR の考え方の入り口になる)

課題2(中): トゥーンシェーディングにする

拡散反射の値を段階的にすると、アニメ調の絵になる。

  1. diffuse を 0〜1 の連続値ではなく、3段階(0.3 / 0.6 / 1.0)に量子化する
  2. 鏡面反射も「一定以上なら白、以下なら無し」の2値にする
  3. さらに輪郭線を足す。視線と法線の内積が0に近い(= 面が視線と平行に近い)ピクセルを黒くすると、シルエットに線が入る

実装が軽いのに見た目が劇的に変わるので、シェーディングの理解を確かめるのに最適。西川本 Ch11 が詳しい。

課題3(難): 光源を増やす、そしてブリン・フォンにする

  1. Light を配列にして、複数の光源の寄与を足し合わせる。色の違う光源を2〜3個置くと、途端に「作られた絵」らしくなる
  2. 距離による減衰を入れる。1 / (1 + k1*d + k2*d^2) の形が定番。光源マーカーを床に近づけたとき、床が局所的に明るくなるか
  3. フォン反射をブリン・フォンに置き換える。反射ベクトル R の代わりに、光の方向と視線の方向の中間ベクトル H を使い、dot(N, H)^shininess とする。
    • 計算が軽くなるか(Reflect が要らなくなる)
    • 見た目はどう変わるか(同じ見た目にするには Shininess を2〜4倍にする必要がある)
    • なぜ現代のエンジンはブリン・フォンを使うのか
