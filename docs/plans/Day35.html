理論の要点

1. PBR の主張は「材質は2つの数で表せる」

物理ベースレンダリングという名前は大げさだが、実装として何が変わるかは案外はっきりしている。

古い流儀は材質を「拡散色 + 鏡面色 + 光沢度」で持っていた。自由度が高すぎるのが問題で、物理的に有り得ない材質が簡単に作れてしまう。「拡散も鏡面も真っ白」は入ってきた光の2倍を返す設定だが、値としては何も止められない。

metallic-roughness はこう置き換える。

  baseColor  … その材質の色
  metallic   … 金属か否か(0 か 1。中間はほぼ無い)
  roughness  … 表面のざらつき(0 = 鏡、1 = つや消し)

自由度が減っているのがミソで、有り得ない材質を作りにくい。そして減らせる根拠が物理にある——世の中の物質は金属と非金属にきれいに分かれるからで、そこを1ビットにしてよい。

非金属(誘電体)金属
拡散反射する(色はここから)しない
鏡面の強さ F00.02〜0.05。ほぼ 0.040.5〜1.0
鏡面の色白baseColor の色が付く

金属が拡散しないのは、中へ入った光が自由電子にすぐ吸収されて出てこないため。だから金属は「映り込みしかない」——鏡がそういうものであるように。

2. マイクロファセット — 面を「微小な鏡の集まり」と見る

Cook-Torrance は、ざらざらの面を顕微鏡で見たら小さな鏡だらけという描像で組み立てる。粗さとは、その鏡の向きがどれだけばらついているかのこと。

そう見ると、鏡面反射の強さは3つの割合の掛け算になる。

  f_spec = D * G * F / (4 * (N・V) * (N・L))

    D … 何枚が「ちょうど V へ返す向き」を向いているか(法線分布)
    G … その鏡が隣の凸に隠れていない割合(幾何減衰)
    F … その鏡がどれだけ反射するか(フレネル)

「ちょうど V へ返す向き」は1つに決まるのがこの式の出発点で、それがハーフベクトル H = normalize(V + L)。反射の法則から、H を向いた鏡だけが L から来た光を V へ返せる。

分母の 4(N・V)(N・L) は、微小面の面積と立体角を投影で数え直すときに出る係数。導出は特論 A-7 にあるが、「投影の数え直し」とだけ覚えておけば実装は書ける。

3. D(GGX)— 正規化されていることが命

  D = α² / (π * ((N・H)²(α² - 1) + 1)²)

GGX が Phong や Beckmann を押しのけたのは裾が長いから。ハイライトの芯のまわりに、ぼんやりした広がりが遠くまで残る。実測した材質はどれもこの裾を持っていて、「金属なのに CG っぽい」の正体はたいていここだった。

いちばん大事な性質は正規化:

  ∫ D(H) (N・H) dω = 1

「鏡の総面積が、面に投影すると 1 になる」という意味。これが崩れると、粗さを変えただけで鏡面の総量が勝手に増減する——明るさが変わるだけなので、絵からは絶対に気づけない。今日の自己チェック(Ctrl+Shift+0)がまずここを見るのはそのため。

α は roughness そのものではない。glTF・Unreal・Unity はどれも

  α = roughness²

とする。物理的にはどちらでもよい(定義域を写し替えているだけ)が、2乗を挟まないとスライダーが使い物にならない。α を直接動かすと 0〜0.2 でハイライトが一気に広がり、残り 0.2〜1.0 はほぼ変化しない。Ctrl+Shift+6 で切り替えて、グリッドの右半分がのっぺりするのを見られる。

4. F(フレネル)— たった1行が金属と非金属を分ける

  F = F0 + (1 - F0) * (1 - cosθ)^5        … Schlick 近似
  F0 = mix(vec3(0.04), baseColor, metallic)

上の行は「浅い角度から見れば何でも鏡になる」という日常の現象。机も紙も、目の高さすれすれから見ると光沢が出る。

そして下の行が metallic-roughness の心臓部で、要点1の表がこの1行に畳んである。metallic が 0 なら F0 は 0.04 の白、1 なら baseColor そのもの。Ctrl+Shift+8 でグリッドの色を金や銅に変えると、金属の行だけハイライトに色が乗るのが見える。

θ に入れるのは V・H(視線と微小な鏡の法線の角)で、N・V ではない。反射しているのは微小な鏡なので、基準はその鏡の法線になる。N・V で書くと粗い材質の縁だけが不自然に光る。

5. G(幾何減衰)— 粗いほど暗くなる理由

微小な鏡は互いを隠す。光が入るときに手前の凸に遮られ(shadowing)、出ていくときにも遮られる(masking)。その残存率が G。

Smith の近似は入りと出を独立と見て掛け合わせる。

  G1(X) = (N・X) / ((N・X)(1 - k) + k)
  G     = G1(V) * G1(L)
  k     = (roughness + 1)² / 8        … 直接光の場合

k の式は物理から出てこない。Disney が実測に合わせて選んだ当てはめで、IBL では α / 2 を使う(Day 36)。同じ G なのに係数が2通りあるのは、このあたりが「理屈と当てはめのつぎはぎ」であることの現れになっている。

G があるおかげで粗い材質は暗くなる。グリッドを見ると、右へ行くほどハイライトが広がり、同時に暗くなるのが分かる——同じ量の光を広い範囲に配っているのだから、当然そうなる。

6. エネルギーの分け前 — 1/π と kD = (1 - F)(1 - metallic)

拡散と鏡面を足すとき、合計が入ってきた光を超えてはいけない。そのための2つの係数が今日から入る。

  kD      = (1 - F) * (1 - metallic)
  diffuse = kD * baseColor / π

(1 - F) は「反射しなかったぶんだけが中へ入る」。(1 - metallic) は「金属は中へ入った光を返さない」。どちらも要点1の物理をそのまま式にしただけになっている。

1/π は Day 34 まで省いていた。ランバート反射を半球全体で積分すると π になるので、1 に戻すために割るのが正しいのだが、Day 9 以来この π は光の強さのほうに吸わせていた(光を弱く持っていた)。

だから式を差し替えるとシーン全体が 1/π に沈む。リファレンスでは Render3D が送る uLightColor に π を掛けて釣り合わせている——Ctrl+Shift+1 で切り替えたときに明るさが揃っていないと見比べられないため。物理的には π を掛けたほうが正しい(uLightColor が放射輝度になる)。

7. 平行光源1つだと金属は黒い。それは正しい

グリッドを出すと、上の行(金属)がほとんど黒くなる。バグではない。

金属は拡散反射をしない。だから見えるのは映り込みだけで、映り込む景色が無ければ本当に黒い。現実の金属が黒く見えないのは、空や壁や自分の手を映しているから。

それを与えるのが Day 36(環境マッピングと IBL)。今日は Ctrl+Shift+7 で「環境光を F0 の色で薄く足す」だけの粗い代用を置いてある——物理的な裏付けは無いが、金属度の効きを見るには要る。

もう1つ、光は式の中でも失われる。Cook-Torrance は微小な鏡で1回だけ跳ねる前提なので、凹凸の中で2回3回と跳ね返る光をまるごと落としている。自己チェックが数字を出す。

粗さ返る光失う光
0.05100.0%0.0%
0.5086.0%14.0%
1.0030.7%69.3%

ざらざらの金属が実物より暗くなるのはこれ。今日はまず「知っていて使っている」状態にするところまでで、補正(Kulla-Conty や Fdez-Agüera の多重散乱項)は Day 36 の発展課題にする。

読み取ってほしいのは順番の必然性で、上から下へ「動かせない理由」がある。

段なぜここでなければならないか
UV が先ずらす前の UV で1枚でも読むと、その成分だけ凹凸から浮く(Day 34)
法線が次BRDF の入力が N なので、差し替えは呼ぶ前に済んでいる必要がある

BRDF は影の後影は BRDF の中身に関係しない係数なので、外で掛けるほうが式が澄む
環境光は最後直接光と足すだけ。AO は環境光にしか掛けない(Day 33 の要点)

CookTorrance が out を5つ持っているのがこの図のいちばん不格好なところで、拡散・鏡面・D・G・F を全部外へ出している。

戻り値1つで済ませるほうがきれいだが、それだと「金属なのに拡散が残っている」「非金属なのに鏡面が色付き」といった取り違えが合成した絵からは絶対に見えなくなる。成分 13〜17 は、そのために外へ出した5つをそのまま画面に出しているだけ。

分岐が多いのは GPU では本来まずい。GPU は近くの画素をまとめて動かすので、枝が分かれると両方の枝を実行してから片方を捨てることがある。本番のエンジンはこれを #define を変えたシェーダバリアントに分けるが、今日は「1本のシェーダで全部見られる」ことを優先した。成分の分岐は画面全体で同じ値を取る(uniform 分岐)ので、実際には安く済んでいる。

FragColor はまだ HDR。金属のハイライトは 1.0 を軽く超えて出る。Day 31 で RGBA16F のシーンバッファを用意しておいたので、ここで切られずに後処理まで届く——8bit(Shift+1)に落とすと、粗さの左端が全部同じ白になるのを確かめられる。PBR と HDR が対で語られるのはこのため。

改造課題

課題1(易): 光源をもう1つ足す

平行光源を2本にして、色と向きを変える。uLightDirection / uLightColor を配列(vec3[2])にして、CookTorrance の呼び出しをループで回すだけ。

ここで BRDF の形が効いてくる。BRDF は「V と L から割合を返す」関数なので、光源が増えても足すだけでよい。1本目のために書いたコードが1行も変わらない。

見どころは金属のグリッド。ハイライトが2つ出て、その2点以外はやはり黒い——光源をいくら増やしても、点や平行光源では映り込みにならないことが体感できる。Day 36 が要る理由がここではっきりする。

課題2(中): 多重散乱の補正を入れて、失われた光を取り戻す

要点7の表で、粗さ 1.0 の金属は光の 69% を失っていた。Fdez-Agüera の近似は、これを数行で埋める。

  E   = 鏡面の方向アルベド(視線角と粗さから引く)
  補正 = 1 + F0 * (1/E - 1)
  specular *= 補正

E は本来 LUT(Day 36 の分割和)から引くが、まずは Pbr.DirectionalAlbedo を CPU で刻んで 32x32 の表に焼き、テクスチャとして渡すのが早い。今日書いた重点サンプリングがそのまま使える。

うまくいけば自己チェックの損失の表が「粗さ 1.00 で 69.3% 失う」から数 % まで縮む。チェックが先にあるので、効いたかどうかを絵ではなく数字で判定できる——今日 CPU 側に式を持った値打ちがここで出る。

課題3(難): 「材質を撮る」ための正しいカメラを作る

いまの材質グリッドは、正面から見た球に光を1本当てているだけ。実務の材質ビューアは、これに加えて

  • カメラを球に対して等距離に置く(いまは平行に並べているので、端の球ほど斜めから見ている)
  • 粗さの刻みを対数にする(0.0〜0.2 に見どころが集中しているので)
  • 背景に階調のあるグラデーションを敷く(縁の明るさが背景に対して読めるように)

をやる。3つ目がいちばん効く。黒い背景だとフレネルの縁が「明るい」としか分からないが、明るい背景と暗い背景の両方に接する球を置くと、縁が背景より明るいのか暗いのかが判定できるようになる。

やってみると分かるが、これは絵作りではなく計測の話。「材質が正しいか」を目で判定できる条件を整える作業で、Day 39 でデモのライティングを組むときに同じ悩みがもう一度出る。

検証の途中で分かったこと

素朴な数値積分では、エネルギー保存を検算できなかった。

最初は半球を 192x192 の格子に刻んで足し込む形でDirectionalAlbedo を書いた。素直で分かりやすいが、結果が壊れた——粗さ 0.05 の金属で「返る光 120.6%」という値が出た。

原因は D のとがり方。粗さ 0.05 なら α = 0.0025 で、ピークの幅は 0.0025 ラジアンしかない。刻み(0.008 ラジアン)より細いので、山を踏み外すか、踏んだ1点に広いマス目の面積を掛けて数えすぎるかのどちらかにしかならない。

解は重点サンプリング。D に比例する確率でハーフベクトルを引き、確率密度で割り戻す。約分すると D がきれいに消えてG * F * (V・H) / ((N・V)(N・H)) だけが残る。同じ 8192 点でも、粗さ 0.05 で 100.0% と正しい値になった。

副産物として Hammersley と ImportanceSampleGgx が手元に揃った。Day 36 の IBL は環境マップの事前積分にこれをそのまま使うので、先に書けたことになる。

非金属は、浅い角度で 1 をわずかに超える。

金属(拡散なし)は全条件で 1 以下に収まったのに、非金属は視線が浅いところで 1.076 まで出た。実装ミスを疑って探したが、式は合っていた。

穴は kD = 1 - F(V・H) の作り方にある。これは「その1本の光線が反射しなかった割合」であって、「鏡面が半球全体で持って行った割合」ではない。浅い角度では F が 1 に近づくのに、拡散側は入ってくる光の平均で減らされるので引き足りない。

正しくやるには鏡面の方向アルベドで拡散を減らす必要があり、それには視線角と粗さの2次元表が要る——Day 36 で焼く分割和の LUT がまさにそれ。今日は「7.6% 超える」という数字を出して知っておくところまでにして、自己チェックの項目名にもそう書いた。

相反性のチェックが落ちたが、悪かったのはチェックのほうだった。

f(V, L) = f(L, V) を 64 通りで確かめる項目が、最大誤差 0.118 で落ちた。Cook-Torrance は D も G も F も V と L について対称なので、破れるはずがない。

原因は試験に使うベクトルで、片方が面の裏側に回っていた。裏なら片方は 0 を返し、もう片方は 0 割り避けのクランプ(max(N・V, 1e-4))が効くので、式のせいではないところで対称性が崩れる。両方を表側に置き直したら誤差 2.11E-008 まで落ちた。

自己チェックが落ちたとき、まず疑うのは実装だが、確かめ方が悪いこともある。

材質グリッドが逆光になっていた。

グリッドを実装して画素を読み出したところ、49 個が軒並みのっぺりした環境光の色になっていた。

デモの太陽(_lightDirection)は画面の奥から手前へ進む向きに置いてある。立方体やモデルを斜めから見るぶんには陰影が付くが、グリッドは正面から見る絵なので、手前の面が全部逆光になる。

材質の見本を撮るときは光をカメラの少し左上に置くのが定石なので、この描画の間だけ uLightDirection を差し替えることにした。併せて光の強さも 0.30 倍にしてある——元の強さだと拡散の行が白飛びして、粗さの違いが消えた。ハイライトのぶんの余地を上に残しておかないと材質が読めない。

球の巻き順は、手で決めずに計算した。

UV 球の三角形を「左下 → 右下 → 右上」で巻いたら内向きになる。経度の増える向きと緯度の増える向きの外積が球の内側を向くためで、間違えると背面カリングで球が丸ごと消える——「実装は合っているのに何も映らない」という、原因の見当が付きにくい壊れ方をする。

赤道上の1点で cross(BR - BL, TR - BL) を実際に計算して外向きを確かめ、「左下 → 左上 → 右上」に決めた。併せて Mesh.ReadIndices を足して、全三角形の幾何法線が頂点法線と同じ側を向くかを自己チェックに入れてある。極で潰れる 96 枚(面積 0 なので向きが出ない)は対象外として数えるだけにした。
