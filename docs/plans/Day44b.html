理論の要点

1. 分離軸定理 — 無限の向きが 15 本に減る

2つの凸形状が離れているなら、その2つを分けてしまう平面が必ず1枚ある。

裏を返すと、どの向きに投影しても重なっているなら当たっている。これが分離軸定理(SAT)で、証明は「凸集合の分離超平面定理」そのもの。

実用にするには「どの向きを試せばよいか」が要る。向きは無限にあるが、凸多面体どうしなら候補は有限個で足りる。

候補箱と箱ではなぜ要るか
それぞれの面の法線3 + 3 = 6 本面と面、面と頂点で分かれる場合を捕まえる
それぞれの辺の向きの外積3 × 3 = 9 本辺と辺が擦れ違う場合を捕まえる

1本の軸を試すのは、線分どうしの重なりを見るだけ。

  重なり = r_A(n) + r_B(n) - |(中心間ベクトル)·n|

r(n) は箱を軸 n に落としたときの長さの半分で、これは各軸の寄与の絶対値の和になる(Box3D.ProjectedRadius)。

  r(n) = |e_x (a_x · n)| + |e_y (a_y · n)| + |e_z (a_z · n)|

絶対値なのは、「どの角がいちばん n の側に突き出るか」を場合分けせずに済ませるため。

1本でも重なりが負なら、その時点で離れている——残りは調べなくてよい。これが SAT が実用になる理由で、離れている組(大多数)は数本で抜ける。

辺×辺の 9 本は本当に要るのか

要る。角どうしが斜めに擦れ違う配置では、面の法線 6 本のどれで見ても重なって見えるのに、実際には離れている。面の法線だけで済ませると、斜めに置いた箱がすり抜ける。

自己チェックはこれを理屈ではなく実物で見せる——ランダムな配置を試して「面の法線だけなら当たったと答えてしまうが、辺の軸を見れば離れている」配置を探し当てる。6 回目の試行で見つかるので、珍しい配置でもない。

いちばん浅い軸を採る

15 本すべてで重なっていたら当たっている。押し戻す向きは重なりがいちばん浅かった軸を採る——そこがいちばん抜けやすい向きだから。深い軸で押し戻すと、床にわずかに沈んだ箱が真横へ吹っ飛ぶ。

ただし辺×辺の軸には 5% の下駄を履かせる。ほぼ平行な2つの辺の外積は長さがほとんど 0 で、正規化すると向きが数値誤差でぐらぐら揺れる。その軸がわずかな差で最小になると、面で触れているのに「辺どうし」と判定されて接触点が1つに落ち、箱が震え出す。

2. 面と面のクリップ — 接触点はこう作る

SAT が「面の軸」を選んだとき、接触点は多角形クリップで作る。手順は4段。

  1. 基準面を決める … 重なりが最小だった軸を持っていたほうの箱の、相手を向いた面
  2. 入射面を決める … 相手の面のうち、外向き法線が基準面と最も逆を向いているもの(= いちばん正面から当たっている面)
  3. クリップ … 入射面の4頂点を、基準面の側面4枚で切り落とす
  4. ふるい … 残った点のうち、基準面より内側(めり込んでいる)ものだけを採る

なぜ「入射面を基準面の枠で切る」のか。触れているのは2つの面の重なっている部分で、凸どうしなのでそれは凸多角形になる。入射面(4角形)を基準面の枠(側面4枚)で切ると、まさにその重なりが出てくる。

床の上に箱を置けば4点。床から半分はみ出せば、はみ出した側の2点が切り落とされて、代わりに床の縁の上に新しい2点が生まれる。自己チェックはこれを「いちばん外の点の x 座標が台の縁とぴったり一致する」で確かめている。

クリップの中身は Sutherland-Hodgman——頂点を順にたどって

  • 今の点が内側なら、その点を残す
  • 今の点と次の点で内外が入れ替わるなら、境界との交点を足す

の2つを繰り返すだけ。Day 8 で視錐台に三角形をクリップしたのと同じ手続きで、2D でも 3D でも形は変わらない。

点の数は減るとは限らない。交点が新しく増えるので、4角形を4枚で切ると最大8つ。そこから4つに絞るのは Day 44a の ContactManifold.Add(深い順に4つ)にそのまま任せる。素朴なやり方で、これを直すのが改造課題2。

辺×辺が選ばれたときは話が簡単で、接触点は1つだけ。角と角がすれ違っている場面なので、触れているのは1点しかない。2つの辺の最近接点を求めればそこが接触点になる。

3. 球と箱 — 最近接点で済む

箱どうしが 500 行を超えるのに対し、球と箱は 50 行ほどで済む。球は「中心から一定の距離」なので、箱の上でいちばん近い点までの距離を半径と比べればよい。

csharp
Vector3 local = box.ToLocal(sphere.Center);                                   // 箱の物体座標へ
Vector3 clamped = Vector3.Clamp(local, -box.HalfExtents, box.HalfExtents);    // 各成分を切り詰める

傾いた箱でも物体座標へ持ち込めば軸に沿った箱になるので、Day 25 の 2D の円と箱(Collision2D.CircleBox)とほとんど同じ形になる。

1つだけ別扱いが要るのは、球の中心が箱の中に入ったとき。最近接点が中心そのものになり距離が 0 なので、法線が決められない。3つの軸それぞれについて「面までどれだけ余裕があるか」を測り、いちばん余裕の少ない面へ押し出す。

これで Collide の表の穴(Day 44a で空けたままだった2つ)が両方埋まる。15 通りのうち、今日で5通り。

4. 積むと、4点を同時に解く意味がもう一度出る

Day 44a の要点5で、4点を順番に解くと床の箱1つでも揺れが止まらない(0.118 rad/s)と書いた。積むと、この偏りが段ごとに重なる。

  • 1段目の箱は、1点目で床を強く押し、残り3点は仕事をしない
  • わずかに傾いた1段目の上面が、2段目を斜めに押す
  • 摩擦の無い世界では、傾いた接触は横向きにも押すので、上の段ほど横へ流れていく

実測で6段の柱が 5 秒で崩れ落ち、横ずれは 10m を超える。同時に解けば横ずれは測定できないほど 0(0.00mm)。

Ctrl+Shift+Alt+7 の意味が、床の箱1つ(Day 44a)よりずっと派手に見えるのが今日。同じつまみ、同じ偏りでも、積み重ねると物の運命が変わる。

組と組の間は順番(ガウス・ザイデル)のままなのも効いている。下の組を先に解くと、その結果を見て上の組が解かれるので、柱の下から上へ荷重が伝わる。

沈むことと崩れることは別の話なのが今日の学び。4点を同時に解いたことで崩れなくなったが、沈むのは直っていない。沈みは「1周ごとにインパルスをゼロから決め直している」ことが原因で、そこは蓄積インパルスと温存(warm starting)の担当になる——Day 43 の改造課題3で予告したとおり。

改造課題

課題1(易): 辺×辺の下駄を外してみる

Sat.EdgeBias は 1.05(辺×辺の軸に 5% の下駄)。これを 1.0 にして、Ctrl+Shift+Alt+2 で「箱を積む」と「箱が転がる」を出す。

  • HUD の 辺: が、面で触れているはずの場面で増えるか
  • 積んだ箱の接触点(Ctrl+Shift+Alt+3)が、4点から1点へ飛ぶ瞬間があるか
  • Ctrl+Shift+Alt+6 の内訳で、辺×辺になった組の法線がどちらを向いているか

下駄は「迷ったら面のほうが正しい」という経験則を数にしたもの(要点1)。理論上の根拠は無いので、外すと何が壊れるかを自分の目で確かめるための課題。逆に 1.5 のように大きくしすぎると、本当に辺どうしが当たっている場面で面が選ばれ、何が起きるかも見てみる。

課題2(中): マニフォールドの点の選び方を直す

ContactManifold.Add は満杯のとき「いちばん浅い点」を捨てている。深さだけで選ぶと、面のごく狭い一角に4点が固まることがある——そうなると面で支えているつもりが実質1点になり、また箱が揺れる。

Box2D と Bullet は広がりを見て選んでいる。

  1. いちばん深い点を1つ採る
  2. そこからいちばん遠い点を採る
  3. その2点が作る線分からいちばん遠い点を採る
  4. できた三角形の外にある点のうち、面積がいちばん増える点を採る

これを Add の代わりに「全部溜めてから4つ選ぶ」形で書き直す(Sat.BuildFaceContact が最大8点をいったん配列に溜めるように変える)。

効果が見えるのは、箱を台の角にわずかに載せたとき。今のやり方だと4点が角に固まるので、Ctrl+Shift+Alt+3 で並びを見比べるとよい。

課題3(難): GJK で置き換えてみる

SAT は「凸多面体どうし」でしか使えない。面と辺を列挙できる形でないと軸の候補が作れないからで、円柱や凸包には向かない。

GJK(Gilbert-Johnson-Keerthi)は支持関数だけで距離を求めるアルゴリズムで、Box3D.Support が既にある(今日の BuildEdgeContact で使っている考え方と同じ)。

  1. Support(direction) だけを使って、2つの形のミンコフスキー差が原点を含むかを判定する
  2. 含んでいたら EPA(Expanding Polytope Algorithm)で最小の押し戻し方向を求める
  3. Sat.BoxBox と答えを突き合わせる自己チェックを書く

接触点の生成は SAT のまま使える——EPA が返す法線から基準面を選べば、今日書いたクリップがそのまま動く。ロードマップで「厳密に必要になったら convex hull + GJK を発展課題として」と書いてあるのがこれ。

検証の途中で分かったこと

最初に書いた解き方では、箱が3段で崩れた。接触を Day 43 と同じく1点ずつ順番に解いていたのが原因で、反復を 50 周に増やしても、角速度の減衰を 0.9/秒 まで上げても直らなかった。

原因を追うと、接触を作った最初のステップで既に角速度が 0.0013 rad/s 立っていた。完全に対称な配置なのに回り始めている——1点目を解いた時点で相対速度が 0 になり、残り3点が仕事をしないので、1点目だけが重さを全部背負っていた。

摩擦が無い世界では、少し傾いた接触は横向きに押す。0.01 rad/s の傾きでも 5 秒あれば 3 度になり、mg·sin(3°) の横向きの力が効いて柱が流れていく。物理的には正しい挙動で、間違っていたのは解き方のほうだった。(このとき直した「同時に解く」は、Day 44 を2日に分けたときに Day 44a へ移した。床の箱1つでも揺れが止まらないことが数字で出たので)

蓄積インパルスを先に試したが、ほとんど効かなかった。Day 43 の改造課題3(そして Day 47)の内容を先に入れてみたところ、3段の柱はやはり崩れた——偏りの原因は反復のクランプではなく、点を順番に解いていることだったので、当然といえば当然だった。蓄積インパルスは「沈み」には効くので、Day 47 の担当のままにしてある。

Span はタプルで入れ替えられない。クリップの入れ物を (polygon, scratch) = (scratch, polygon) で交換しようとしたらCS9244 で弾かれた。Span<T> は ref 構造体なのでタプルに入れられない(タプルはヒープに載りうる)。一時変数で書くしかない。

接触点の光る玉は、クリップの確認にも効いた。クリップが効いていないときは玉が箱の角に飛び出るので一目で分かる。Day 44a で「Program 側に 20 行書けば済む」と書いた道具が、今日いちばん働いた。
