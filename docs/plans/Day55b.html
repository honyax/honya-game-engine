理論の要点

1. モーションブラー — 速度バッファを読み、シャッターが開いている割合を掛ける

Day 54 の速度バッファは「この画素は前のフレームで画面のどこに居たか」(UV、前 → 今)。これはそのまま1フレームの間の動きでもある。

  尾の長さ [画素] = 1フレームの動き [画素] × シャッターが開いている割合
  尾は今の位置を真ん中にして前後に伸ばす(片側は半分)。半分の長さの上限は 16 画素(升目の大きさ。Day 55a の要点5)

割合の決め方は2通り(F9)。

決め方割合フレームレートが半分になると
シャッター角(映画の決め方。180° が定番)角度 / 360(0.5)1フレームの動きが倍になるので、尾も倍
シャッター速度(1/120 秒)1/120 ÷ 1フレームの時間1フレームの動きは倍、割合は半分で、尾は同じ
 
  画面を 600 画素/秒 で横切る物(自己チェック):
    180°       → 30fps 10.0 / 60fps 5.0 / 144fps 2.1 画素
    1/120 秒   → 30fps  5.0 / 60fps 5.0 / 144fps 5.0 画素

L キーで1ステップ 20ms の負荷を掛けて 6.2fps(1フレーム 161ms)まで落とすと、HUD の「開いている割合」は角度で 50%、秒で 5% になった。フレームレートが揺れるゲームでは、秒で決めるほうが尾の長さが揃う。映画のように一定のフレームレートなら、どちらでも同じ。

2. 尾の混ぜ方 — 手前・奥・両方の3つの場合(McGuire 2012)

尾も「点が道のりに沿って光を配る」処理なので、Day 55a のボケと同じく裏返して集める(Day 55a の要点4)。読む向きは近所の升目でいちばん速い速度。自分が止まった背景の画素でも、すぐ隣を速い物が横切れば、その尾が自分の上まで伸びてくるから。

向きに沿って 15 点を読み、読んだ点 Y を自分 X に混ぜてよい度合いを3つの場合の和で決める。

場合混ぜる度合い絵の上では
Y が手前Y の尾が X まで届く分(円錐: 尾の先ほど薄い)手前の物の尾が、背景の上へ伸びる
Y が奥X の尾が伸びている範囲の分X が動いているので、後ろの物が透けて見える
両方とも動いている互いの尾の中にいれば(円柱)同じ物の中の尾

自分の色は重み 1 / 自分の尾の長さ で始める(長い尾ほど1画素あたりに置いていく光は薄い)。奥で動く物の尾は、手前で止まっている物には掛からない——手前が隠しているから(自己チェック: 手前の板の最大 0.0000 / 反対側の背景 0.200)。

15 点を等間隔に読むと、明るい物が 15 枚の写しになって縞に見える。読む位置を画素ごとに少しずらす(Jimenez 2014 の interleaved gradient noise)と、縞が細かいざらつきに変わる。

升目で広げないと(F10)、止まった背景の画素は自分の速度(0)で読むので何も集めず、尾が物の輪郭の中に閉じ込められる (自己チェック: 1フレーム 16 画素で動く棒の外へ、升目ありは 3 画素、なしは 0 画素)。

3. 並び — 被写界深度の後ろ、ブルームの前、HDR のまま

モーションブラーは Day 55a の被写界深度のすぐ後ろに置く。TAA の後ろ・ブルームの前・HDR のままという理由は被写界深度と同じ(Day 55a の要点7)で、尾も「近所の光の量を混ぜる」処理なので、明るい点はまず線に伸ばしてからにじませる。

2つの並びは 被写界深度 → モーションブラー。本物のカメラでは同じ露光の中で同時に起きることなので、どちらを先にしても近似になる(どちらの段も、ぼける前の輪郭について測った奥行きと速度を読んでいる。今日残した歪みの3つ目)。

地図は2人ぶんを1回だけ作る。被写界深度だけのフレームは速度を読まず(Day 55a のまま)、ブラーだけのフレームはレンズの係数を 0 にする(錯乱円が全部 0)。両方なら、速度もレンズの係数も入れて1回。別々に作ると、地図の4パスが2回になる。

モーションブラーも「このフレームのカメラの数字」と速度が挿さっているときだけ掛かる(PostProcess.Frame と Velocity)。自己チェックが後処理を単独で回しても割り込まない(挿さない 1 パス / 挿す 9 パス)ので、Day 38〜55a の自己チェックは入れたままでも全部通る。

今日足したものは、どこに繋がったか

MotionBlur は MotionVectors を知らない。速度は PostProcess.Velocity にテクスチャで挿さっているだけで、それを TAA も読み、ブラーも読む。Day 54a の設計書に「速度を作る側を1行も変えずに、読む側を足すだけで済む形になっている」と書いた、その形になった。

DepthOfField と MotionBlur は Camera を知らない。数字は CameraFrame で届く。TemporalAA がずらしを Vector2 で返して Camera を知らずに済ませたのと同じ線で、自己チェックは 128x64 の作り物の絵に「ピント 2m、無限遠のボケ 8 画素」「1 フレーム 16 画素で動く棒」のような数字を直接並べて、ボケと尾の式を確かめられる。

BlurField の地図は、2人が1回作ったものを読む(Day 55a で速度の口を空けておいたのがここで効く)。被写界深度だけのフレームは速度を読まず(uHasVelocity = 0)、ブラーだけのフレームはレンズの係数を 0 にする(錯乱円が全部 0)。奥行きに戻す式が1か所で済んだのが、共通にした値打ち。

ぼけの地図ができるまで — 地図・横・縦・近所

深度をそのまま 16F に入れず、奥行きに戻してから入れる。透視投影の深度は 1/z に並ぶので、5m 先から 100m 先までが 0.98〜1.0 に押し込まれている。16F は 1.0 のそばで 0.0005 刻みしか持てず、1刻みで 67m から 100m までが同じ値になる。奥行きに戻してから入れれば、10m 先で 8mm 刻みが残る。

今日から速度が流れ込む(Day 55a では uHasVelocity = 0 で閉じていた口)。速度は長さで比べて、向きごと覚える。x と y を別々に最大にすると、どの物も動いていない斜めの向きができあがる(blur-tiles.frag / blur-max.frag)。

同じ blur-max.frag を2回使う。「窓の中の最大」を、窓の大きさと歩幅を uniform で変えて、升目の縦の段((1, 16) の窓)と近所の段((3, 3) の窓)に使い回す。これが Day 55a で Shader.SetInt2 を足した理由。

1画素の尾が決まるまで(モーションブラー)

関門が早いのがモーションブラーの安さ。止まった絵では近所の升目の速度が 0 なので、ほとんどの画素が1回読んで帰る(自己チェック: 止まった絵は1画素も変わらない)。カメラを振ると全部の画素が 15 点を読むので、GPU の時間は動きの量で変わる。

手前・奥は「なめらかに」決める(SoftDepth = 0.1m)。同じ面の上の2画素は、深度の精度の都合で少しずれることがあるので、0 か 1 かで切るとちらつく。

改造課題

課題1(易): 読む位置のずらしを切って、縞を見る

motion-blur.frag は尾に沿って 15 点を読むとき、読む位置を画素ごとに少しずらしている(interleaved gradient noise。要点2)。このずらし(jitter)を 0 にすると、明るい物の尾が 15 枚の写しになって縞に見える。カメラを素早く振り、壁のレンガの明るい目地や、「ディファード」ページで撒いた光(F4 で夜、F3 で点光源 64 個)の尾を見比べる。ずらしは縞を細かいざらつきに変えているだけで、光の量は変えていない——ON と OFF で絵全体の平均がほとんど変わらないことも確かめる。

課題2(中): 露出を F 値とシャッターから決める(物理カメラ)

いまの明るさは露出(Day 31)が別に決めていて、F 値を絞っても、シャッターを速くしても絵は暗くならない。本物のカメラは、F 値の2乗に反比例し、露光の時間に比例して光を溜める。写真の露出値 EV100 は

  EV100 = log2(F 値² / 露光の時間[秒])        (感度 ISO 100 のとき)

で、露出を 1 / (1.2 × 2^EV100) にすると、F 値とシャッターから明るさが決まる(Frostbite の物理カメラの式)。MotionBlur.OpenFraction × フレームの時間が露光の時間なので、それと DepthOfField.FNumber から露出を出して合成の段に渡す。確かめ方: F 値を 1.4 → 2.8 にすると絵が 1/4 の明るさになり、シャッター角を 180° → 360° にすると 2 倍になる。「よくボケる絵は明るく、よく流れる絵も明るい」——被写界深度とモーションブラーが、露出という同じ財布から払っていることが見える。

課題3(難): カメラのブラーを切って、物のブラーだけにする

乗り物酔いを避けるため、多くのゲームは「カメラのモーションブラー」を別に切れる。速度バッファの中身は「カメラの動き」と「物の動き」の和なので、カメラの動きだけの速度を引けば、物の動きだけが残る。

カメラの動きだけの速度は、Day 54a の速度(camera-velocity.frag)と同じ式——深度から戻した点を前のフレームの行列で写し直したもの。MotionVectors に前のフレームのビュー射影を読む口を足し、CameraFrame に再投影の行列を入れて、motion-blur.frag で同じ計算をして引く(升目の最大もこの「引いたあとの速度」で取り直さないと、読む向きがカメラの動きのままになる。blur-tiles.frag にも同じ引き算が要る)。確かめ方は、プレイアブルデモでキツネを歩かせたとき、地面は流れず、キツネの脚だけが流れること。

1. ゆっくりのカメラワークでは、モーションブラーが目で拾えなかった(今日の冒頭の話)。カメラワークの移動中に撮った ON と OFF は、見比べてもほとんど同じだった。升目を見ると尾の半分の長さは 1〜2 画素で、60fps・180° では「1秒に 60 画素動く物の尾は 0.5 画素」にしかならない。モーションブラーが見えるのは、1フレームに何画素も動くとき(カメラを素早く振る、走る)。30fps のゲームで効き目が大きいのは、1フレームの動きが倍になるから(要点1)。完成条件では、同じ姿勢・同じ速さ(1 フレーム 1.5 度)で ON と OFF を撮るために、カメラを1フレームおきに行き来させた。
