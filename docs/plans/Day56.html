今日いちばん大事な3つ

1つ目は「灯りは、照らす側と見える側の2つでできている」。ラスタライザの点光源は壁や床を照らすが、自分は画面に1画素も写らない。光る材質(EmissiveFactor)は光って見えるが、まわりを1画素も照らさない。2つは別々の仕組みなので、片方だけだと「光っているのに何も照らさない窓」か「何も無いところから差す光」になる(要点1)。そこで JSON の1つの項目に両方を書き、色と揺らぎを共有させる。

csharp
// SceneLights.Evaluate(Day 56)。照らす側と見える側に、同じ明るさの倍率を掛ける
_lights[i] = new PointLight(fixture.Position, fixture.Radius, fixture.Color * (fixture.Intensity * brightness));
Vector3 emissive = fixture.Color * (fixture.Glow * brightness);

foreach (Material material in fixture.GlowMaterials)
{
    material.EmissiveFactor = emissive;
}

2つ目は「照らす側の置き場所は、見える側から決める」。街灯なら光るガラスの部品の真ん中、窓なら光る板の 40cm 手前。JSON に座標を書かなくてよく、街灯を動かせば光も付いてくる。板の上ちょうどに置くと、板を貼った壁が照らされない——壁の面の上にある点光源は、壁から見ると真横(N·L = 0)に居るから(要点2)。

3つ目は「推奨項目の統合は、表に載せるだけ」。Day 40 の機能表に灯り・被写界深度・モーションブラーを足し、FXAA の項目を AA に置き換えた。完成版は _features.SetAll(true) の1行で Phase 6〜8 の 15 項目が入る。AA の ON は TAA に決め打ち——FXAA と TAA を別の項目にすると、「全部 ON」で両方が掛かって TAA が均した縁を FXAA がもう一度ぼかす(要点6)。

理論の要点

1. 灯りは2つでできている — 照らす側と見える側

照らす側(点光源。Day 52)見える側(光る材質。Day 32)
仕組み画素シェーダが光のループで足す(PointLightContribution)画素シェーダが最後に足す(uEmissiveFactor)
画面に写るか写らない(大きさを持たない点)写る(板やガラスの形そのもの)
まわりを照らすか照らす(届く距離 radius まで)照らさない
ブルームとボケ照らされた壁の明るさぶんだけここが効く。1.0 を超える発光がにじみ、ピントを外すと丸いボケになる

ラスタライザでは、この2つがまったく別の計算になる。本物のカメラが写す電球は1つなのに、ゲームの絵では2つに割れている。パストレーサ(教養編 Day 60)では、光る面そのものが光源になるので割れない——割れているのはラスタライザの都合。

割れているものは、揃えるのが人の仕事になる。2か所に書くと、片方だけ直す日が必ず来る(Day 40 の機能表で「状態の置き場所は1つ」と決めたのと同じ判断)。そこで1つの項目に書き、SceneLights.Update が毎フレーム同じ明るさの倍率を両方に掛ける。

揃えるものどう揃うか
色項目に1つだけ書く(color)。照らす側 = 色 × 強さ、見える側 = 色 × 明るさ
揺らぎ同じ時刻の同じ倍率(Brightness(i, t))を両方に掛ける。炎が沈めばガラスも床の光だまりも同じだけ沈む
点け消し消すと照らす側の列が空になり、見える側の発光が 0 になる(ガラスはただのガラスに戻る)

揺らぎは時刻の関数(値ノイズ)にしてある。Day 52 の群れと同じで、前のフレームから積み上げないので、60fps でも 144fps でも同じ時刻に同じ明るさになる(自己チェック: 1秒後の差 0.0000)。揺らぎを2乗してから引くので、ふだんはほぼ満点で、ときどき沈む(自己チェック: 範囲の真ん中より明るい時間 77%)。

2. 照らす側の置き場所 — 見える側から決める

JSON に position を書かなければ、見える側から決める。

見える側照らす側の置き場所例
小物の部品を光らせる(glow.prop + glow.match)その部品の真ん中(境界箱の中心)街灯のガラス → 電球の位置(-3.40, 3.32, -4.00)
光る板を足す(glow.size + rotation + position)板の中心から、板の向きに 40cm 手前左の壁の窓 → 壁から 42cm

板の上ちょうどに置くと、板を貼った壁が照らされない。壁の面の上の点光源は、壁のどの画素から見ても真横に居る(N·L = 0)。どれだけ手前に出すかで、壁の光だまりの大きさが決まる。窓の光(届く距離 5.5m)を壁から h だけ離したときの、壁の上の明るさ:

板の大きさの半分くらい手前に出すと、光だまりが板と同じくらいの幅になる。今日の 40cm(DemoScene.PanelLightOffset)はそこから決めた。

街灯は逆で、照らす側は光るガラスの中にある。ガラスの外側の面は、中の光から見て裏を向いている(N·L < 0)ので、ガラスは中の点光源では1画素も明るくならない——見える側(発光)が要る理由がここにもある。F7 で照らす側に玉を出すと、窓の玉は板の少し手前に浮き、街灯の玉はガラスに隠れて見えない。

3. 明るさは2本、色は1本

照らす側の強さ(intensity)と見える側の明るさ(glow.strength)を別々に書く。色は共有する。

分けたのは、見える側の明るさが、ブルームとボケと色の飽和で決まるから。

灯り照らす(x 強さ)見える(x 明るさ)決め方
街灯14.0(届く 9m)6.0ガラスは眩しくてよい。白く飛んでブルームでにじむのが街灯らしい
窓6.0 / 4.01.1暗めに。3.0 だと白い長方形に飛び、斜めから見ると細い光の線になって目を引く
看板6.02.55.0 だと赤が 1.0 を超えて頭打ちになり、白っぽい桃色に転ぶ(露出 1.3 のとき)
裏口の蛍光灯3.04.0蛍光灯は白く飛んでよい。揺らぎを深く(0.75)して切れかけにする
ランタン5.04.0ガラスの模様は発光テクスチャが持つ。こちらは色と明るさだけ

物理で揃えるなら、見える側の輝度 × 光る面の面積 ≈ 照らす側の光度、という関係がある(Frostbite の講義ノート 4.8)。ただし今日の点光源の強さは「距離 0 のときの明るさ」で、分母に + 1 の入った嘘の単位(Day 52b の要点2)なので、この式に乗らない。色だけは物理に関係なく必ず揃える——橙の窓から青い光が差すことは無い。明るさは露出を決めてから目で合わせた(今日残した歪みの1つ目)。

4. 夜の露出 — 暗くしたら上げる

Day 52 の「夜」は、太陽と空を 3% に落とすだけで露出はそのままだった(Program.NightDim の決め打ち)。光の数を目で数えるための窓としてはそれでよかったが、夜の絵としては灯りの届かないところが真っ黒で、通りの形が読めない。

本物のカメラは暗くなれば露出を上げる(人の目も瞳孔を開く)。今日は夜の強さと露出をシーンの持ち物にした(lighting.night)。

夕暮れ夜(完成版)段 [EV]
太陽1.00.05(月明かりの代わり。向きは太陽のまま)−4.3
空(IBL)1.00.07−3.8
露出0.51.3+1.4
灯りの照らす側同じ同じ0

露出を 1.4 段上げたので、月明かりの当たるところは夕暮れより 2.9 段暗く、灯りは 1.4 段明るく写る。夕暮れに灯りを点けても(F4)光だまりがほとんど見えないのは、灯りが変わらないのに太陽が 20 倍明るく、露出が 1.4 段低いから。

太陽を 0 にしないのも決めたこと。点光源は影を持たないので、太陽を切ると影が1つも落ちなくなる。5% の月明かりが、夜の通りに長い影を残している。

demo-v1.json は night を書いていないので、Day 52 と同じ夜(太陽と空 3%、露出は昼のまま)になる。3% の決め打ちは DemoScene.DefaultNightScale に移した(値は同じ)。

課題2(中): 夕暮れから夜へ、4 秒かけて移る

いまの時間帯(F4)は一瞬で切り替わる。0〜1 の「夜の度合い」を持ち、4 秒かけて動かす。

  • 太陽と空の倍率は 1 → night.sunScale を度合いで補間する。露出は段(対数)で補間する——0.5 と 1.3 を素直に線形で混ぜると、暗い側で速く、明るい側で遅く変わって見える
  • 灯りは度合いが 0.5 を超えたあたりから smoothstep で点ける(街灯は日が沈んでから点く)。SceneLights.Update に明るさの倍率を1つ渡せば、照らす側と見える側が一緒に点く
  • ApplyDemoLighting は色調整も入れ直すので、毎フレーム呼んではいけない。毎フレーム変わるもの(太陽の色・空の強さ・露出)だけを別の関数に切り出す

移っている間にキツネを歩かせると、TAA の履歴が明るさの変化にどれだけ付いてくるか(疑いが効いているか)も見える。

課題3(難): 街灯に影を付ける

灯りは影を落とさない(今日残した歪みの3つ目)。全方向の影(キューブマップ 6 枚)は重いので、街灯を真下向きの光とみなして、深度を1枚だけ焼く。

  • ShadowMap(Day 33)は太陽用の平行投影。街灯の位置から真下を見る透視投影(画角 120 度ほど)の行列で、同じ depth.vert を使って深度を焼く
  • textured.frag の点光源のループで、街灯の番号(灯りの 0 番)のときだけその深度と比べて影を掛ける(CurrentLights は灯りを先に並べるので、0 番は街灯のまま)
  • 透視投影の深度は 1/z に並ぶ(Day 7)ので、バイアスは太陽の影と同じ値では合わない。Day 33 のアクネとピーターパンの間を、もう一度探すことになる

確かめ方は、夜の街灯の下でゴミ箱とタイヤの影が、街灯から放射状に伸びること(月明かりの影は平行に伸びる)。
