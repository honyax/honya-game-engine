Day 69 で顔が動くようになった。今日は髪を動かす。

VRM の揺れもの(VRMC_springBone)は、Day 43〜47 で作った剛体の物理とはまったく別物だ。質量も慣性テンソルも接触の連立も持たず、骨の先端の点1つを、前のステップに動いた分だけ動かし続ける(Verlet 積分)。そこへ「ファイルの形へ戻す力」と「重力」を足し、骨の長さへ戻し、体の球から押し出す。決まった先端の向きへ骨を回せば、髪の頂点は Day 41 からのスキニングでそのまま曲がる。

ロードマップの注意書きのとおり、体が動かないと揺れない。アニメーションが入るのは Day 71 なので、今日は骨を手で動かして確かめる(首を振る・腰をひねる・跳ねる・置き場所ごと回す)。そして4つ目の「置き場所ごと回す」で、アバターを丸ごと回しても髪がまったく揺れないという、今日いちばん大事な現象に出会う。

今日いちばん大事な3つ

1つ目は「動かすのは点で、骨はその点を向くだけ」。揺れものの状態は、関節ごとの先端の点(今と1つ前)の2つだけだ。

csharp
// VrmSpringBone.Integrate(Day 70)。three-vrm の VRMSpringBoneJoint.update と同じ形
次 = 今 + (今 - 前) x (1 - dragForce)        // 慣性
     + 戻す向き x stiffness x dt              // 硬さ(ファイルの形の向きへ)
     + 重力の向き x gravityPower x dt          // 重力

決まった点を骨の長さへ戻し、体の球から押し出し、その向きへ骨を回す(要点2)。速度という変数は無く、「今 - 前」が速度の代わりになっている。

2つ目は「center が揺れの基準」。先端の点をどの座標で覚えるかを、鎖ごとに center で決める。AvatarSample_A は全部 Root(アバターのいちばん上のノード)なので、Root ごと動いた分——置き場所の行列で回した分や、Day 73 でキャラが歩いた分——は先端も一緒に運ばれて、揺れに入らない。揺れるのは、Root から見て体が動いたとき(首・腰)だけ。上の実験台の「置き場所ごと動かす」で、center を切り替えて見比べられる。

3つ目は「刻みを固定したら、体の動きも刻みの時刻で渡す」。dragForce は「1ステップで慣性を何割削るか」なので、ステップの長さが画面の速さで変わると揺れ方が変わる。そこで 1/60 秒の固定の刻みで回す。ところが固定にしただけでは足りず、30 fps の画面で1フレームに2ステップ回すとき、2回とも今の体を見せると 60 fps より揺れ方が大きく変わる(2 秒後の曲がりが 48 度 → 35 度)。前のフレームの体との間を補間して渡すと、30 / 60 / 144 fps がそろう(要点5)。

理論の要点

1. 揺れものは「先端の点」を Verlet で動かすだけ

関節1つが持つ状態は、先端の点の今と1つ前の位置だけ。速度は持たず、差 今 - 前 を速度の代わりにする(位置 Verlet)。1ステップで足すのは3つ。

項式意味
慣性(今 - 前) x (1 - dragForce)前のステップに動いた分だけ、今のステップも動く。dragForce はその分を1ステップで何割削るか(0.4 なら 40%)
硬さ戻す向き x stiffness x dtファイルの形の骨の向き(長さ 1)へ、1 秒あたり stiffness m だけ寄せる
重力gravityDir x gravityPower x dt決めた向きへ、1 秒あたり gravityPower m だけ寄せる
  • 硬さと重力は「力」ではなく「移動量」。dt を1回掛けるだけで、dt² ではない。名前は力でも、効き方は「毎秒どれだけ寄せるか」の速さ。仕様もこの形で値を決めている(自己チェック2: 硬さ 1 で 1/60 m = 1.667cm、重力 0.5 で 0.833cm)
  • 硬さは角度によらず同じ大きさ。足すのは長さ 1 の向きなので、5 度ずれていても 90 度ずれていても、1ステップで寄せる量は同じ。ばね(ずれに比例する力)とは違う
  • 体が止まれば、先端はファイルの形の位置に止まる。戻す向きと今の向きが一致すれば、硬さを足しても長さの拘束で同じ所に戻る。揺れるのは、体が動いて「戻す先」が先端から離れたときだけ

上の実験台で、抵抗を 0 にして首をかしげ、「動かさない」に戻すと、しばらく揺れ続ける。硬さを 0 にすると、揺らした髪は戻らない(実機の F7 で x0 にすると、髪が跳ね上がったまま 167 度曲がって止まる)。

2. 長さを戻し、先端の向きから回転を逆算する

積分した点は骨の長さからずれるので、根からの向きのまま、骨の長さの所へ戻す(ConstrainLength)。実験台で「長さの拘束: なし」にすると、硬さが同じ向きを毎ステップ足し続け、慣性に積もって、先端の点(橙)が骨の先からどこまでも流れていく。

点が決まったら、骨をその点へ向ける。

csharp
// VrmSpringBone.StepSpring の 4 段目
Matrix4x4.Invert(restWorld, out Matrix4x4 restWorldInverse);           // ファイルの回転のままの骨の逆
Vector3 to = Normalize(Vector3.Transform(nextWorld, restWorldInverse)); // 先端を骨のローカルへ
joint.Rotation = Quaternion.Normalize(joint.RestRotation * FromTo(joint.BoneAxis, to));
  • 鎖は根から先へ。1つ目の骨を回すと2つ目の骨の根が動くので、2つ目は1つ目を回し終えてから決める。鎖の世界行列は鎖の中で掛け進める(設計書)
  • 最後の関節は先端の印で、揺れない。ファイルの joints が 3 個なら、揺れる骨は 2 本(AvatarSample_A の 46 個の関節のうち、揺れるのは 34 個)
  • 移動と拡大はアニメーションの値のまま。揺れものが書くのは回転だけ

自己チェック6 は、硬さ 0・抵抗 1(慣性なし)の振り子を 10cm 横へずらし、骨が置いてきた先端を向くこと(26.57 度 = atan(10/20))、子のノードがその点にちょうど来ること(ずれ 0.0001mm)を確かめる。

3. コライダー — 球とカプセルから押し出す

先端の点は半径 hitRadius の球として、体のコライダー(ノードに付いた球かカプセル)と比べる。

形距離(表面どうし)押し出す向き
球|点 - 中心| - 半径 - hitRadius中心から点へ
カプセル線分 head–tail の、点にいちばん近い所を中心にした球と同じ線分から点へ(線分に垂直。端より外は端から)

距離が負なら、その分だけ外へ押し出し、もう一度長さを戻す。この「押し出してから長さを戻す」がくせ者で、根がコライダーに近いと、長さを戻したときにまた少し中へ入る(下の実験台で根を近づけると見える)。首を振ったときのめり込みは、コライダーを切ると最大 41.0mm、効かせても最大 15.8mm 残る(自己チェック13)。押し出しは「次のステップでまた押す」を繰り返して、だんだん外へ出す形になっている。

ファイルの形の時点で、もう毛先がめり込んでいる。AvatarSample_A の横と後ろの毛先は、胸の上(upperChest)の球に最大 31.6mm、腕の付け根の球に 22.3mm 入った形で書き出されている。だから揺れものを入れた最初の1秒で毛先が押し出され、じっと立っていても 7 個の関節が押された形(最大 48 度)で止まる。肩に髪がかかった形を、作者がコライダーで作っているわけだ(three-vrm でも UniVRM でも同じ式なので同じ形になる)。

4. center — 先端をどの座標で覚えるか

先端の点(今と前)は世界の座標で覚えてもよいし、あるノード(center)の座標で覚えてもよい。違いはそのノードごと動いたときに出る。

先端を覚える座標center ごと(置き場所ごと)動くとcenter から見て体が動くと
世界(center 無し)先端は世界に取り残される → 遅れて揺れる揺れる
center のノード(AvatarSample_A は全部 Root)先端も一緒に運ばれる → 揺れない揺れる

実機の「置き場所ごと回す」(F2 の最後)は、ノードの姿勢を1つも変えず、置き場所の行列だけを左右に 60 度回す。center が Root(置き場所と一緒に回る)なら、先端の速さは 0.2cm/s(止まっているのと同じ)、center を外すと 150cm/s で髪が振り回される。

なぜ作者は Root を center にするのか。Day 73 でキャラが歩き回ると、置き場所の行列が毎フレーム数 cm 動き、振り向けば一気に回る。世界の座標で揺らすと、歩く・走る・振り向く・ワープするたびに髪が大きくなびく。center を Root にすると、それらは全部揺れに入らず、揺れるのはアニメーションが体を動かした分(歩きの上下動・腕振りにつられた胸の回転)だけになる。走ってなびかせたいなら、center を外すか、Day 73 で移動の速さを風のように足す(改造課題1)。

コードでは、先端の点を center の座標で積分し、世界へ戻して長さとコライダーを当て、また center の座標へ戻して覚える(StepSpring の 2〜3 段目)。center を変えると覚えている座標の意味が変わるので、その鎖の先端を置き直す(Spring.StateCenter)。

5. 固定の刻みで回し、体の動きは刻みの時刻で渡す

dragForce は「1ステップで慣性を何割削るか」。three-vrm は描くフレームの dt をそのまま使うので、画面の速さでステップの長さが変わり、揺れ方も変わる。今日は Day 19 の固定タイムステップと同じく、1/60 秒の固定の刻みで回す(StepSeconds)。

ただし固定にしただけでは足りなかった。30 fps の画面では1フレームに2ステップ回すが、2回とも「今のフレームの体」を見せると、体の動き2ステップ分が1回目に一度に入る。揺れものは非線形(硬さが角度によらず一定・長さの拘束)なので、この入り方の違いが揺れ方を大きく変える。

体を 30 度 x sin(2πt) で揺すって 2 秒後の曲がり(振り子の台、硬さ 0.8・抵抗 0.4)30 fps60 fps144 fps
可変 dt(three-vrm の形)51.05 度48.36 度45.83 度
固定の刻み・体は今のフレームのまま35.16 度48.36 度47.25 度
固定の刻み・体をステップの時刻へ補間(今日)48.36 度48.36 度48.36 度

(表は下の実験台と同じ式を倍精度で回した値。C# の実機では行列の線形補間で体を戻すので、30 / 144 fps が 60 fps と 0.83mm 以内に来る。自己チェック9)

補間は「鎖の外」の行列だけでよい。鎖の根の親(頭や胸の上)、center、コライダーのノード。この3つの前のフレームの値を覚えておき、ステップの時刻に合わせて Matrix4x4.Lerp で混ぜる(OuterWorld)。鎖の中は、補間した根の親から掛け進めるので、自然にステップの時刻の値になる。

csharp
// VrmSpringBone.Update。30 fps なら steps = 2、1回目は alpha = 0.5(前のフレームとの真ん中の体)
float behind = _accumulator + ((steps - 1 - step) * StepSeconds);   // フレームの終わりから、どれだけ前か
float alpha = Math.Clamp(1.0f - (behind / dt), 0.0f, 1.0f);
StepSpring(pose, spring, alpha);

今日残した歪み

1つ目: 鎖は親子が続いている前提。鎖の中を掛け進めるので、joints の間に揺れないノードが挟まっていると、そのノードの移動と回転が抜け落ちる(読むときに「親が1つ前の関節ではない」と知らせるだけ)。AvatarSample_A の 12 本は全部続いている(自己チェック11)。直すなら改造課題3。

2つ目: 補間は行列の線形補間。1フレームの間の動き(数度)なら回転の縮みは見えないが、置き場所がワープしたフレーム(裏通り ↔ 床の上)では途中の行列が意味を持たない。center が Root なら置き場所の動きは揺れに入らないので、今のアバターでは表に出ない。

3つ目: 144 Hz の画面では髪が 60 Hz でしか動かない。ステップを回さないフレームは、前に決めた回転を書き戻すだけ。体は 144 Hz で滑らかに動き、髪だけが 60 Hz の段で付いて来る。Day 19 と同じく、描くときに前のステップとの間を補間すれば消える(改造課題2)。開発機は 60 Hz なので見えていない。

4つ目: 拡大を見ていない。hitRadius とコライダーの半径は、ノードの拡大を掛けずにそのまま使う(three-vrm も同じ)。アバターを 2 倍に置くと、髪が体から浮いて見える。

5つ目: 押し出しきれない。押し出してから長さを戻すので、根がコライダーに近いとまた中へ入る(要点3)。首を振ると最大 15.8mm 残る。仕様の式どおりで、作者もこの式で形を決めているので、今日は直さない。

6つ目: 体の動かし方と腕のカプセルが Program.cs に直書き(ApplyVrmMotion / VrmArmCapsule)。動かし方は Day 71 の VRMA に置き換わる。カプセルは本来作者がファイルに書くもので、見せるための仮置き(Day 69 の自作の表情と同じ扱い)。

試して分かったこと

  • ファイルの形で毛先が体にめり込んでいる。最初、じっと立っているだけで髪が 50 度曲がり、式の誤りを疑った。コライダーを切ると 0.03 度で止まるので、ファイルの形の毛先が胸の上の球に最大 31.6mm 入っていて、それが押し出されていた。押された形で止まり、3 秒と 4 秒で 0.0076 度しか変わらない(自己チェック12)
  • 固定の刻みにしただけでは揺れ方がそろわない。30 fps で 2 秒後の曲がりが 35.16 度(60 fps は 48.36 度)と、可変 dt(51.05 度)より悪くなった。体の動きを補間して渡したら 48.36 度にそろった(要点5)
  • 1/144 を 288 回足しても 2 秒に届かない。float の端数で 120 回目のステップを取りこぼし、144 fps だけ 4.6cm ずれた。数えるときに 10 マイクロ秒だけ甘くした
  • 抵抗 0 でも、いずれ止まる。長さの拘束が、骨に沿った向きの速さを毎ステップ捨てるから。振り子の台では、止めてから静まるまで 抵抗 0.4 で 0.42 秒、0.05 で 1.52 秒、0 で 2.73 秒
  • 曲がりの角度では「揺れているか」が読めない。じっと立っていても押された毛先が 48 度を示す。HUD には先端の速さ(center の座標)を足した。置き場所ごと回して center が Root なら、ここがほぼ 0 になる
  • 硬さ 0 の髪は戻らない。首を振ってから止めると、跳ね上がった形(167 度)のまま止まる。重力も 0 なので、どこにも引かれない

改造課題

課題1(易): 風を吹かせる

VRM 1.0 の揺れものに風は無い。VrmSpringBone に Wind(世界の向きと強さ。1 秒あたりの移動量)を足し、Integrate に重力と同じ形の項を1つ足す。強さを時間で揺らす(sin を2つ重ねる)と、それらしくなる。center の座標で積分しているので、風の向きは重力と同じく worldToCenter で回してから足すこと。Day 73 でキャラが走るとき、走る速さの逆向きの風を足せば、center が Root のままでも「走ってなびく」が作れる。

課題2(中): 144 Hz の画面で髪をカクつかせない

今日残した歪みの3つ目。Joint に1つ前のステップの回転を覚えさせ、ステップを回さないフレームでは、持ち越した端数 _accumulator / StepSeconds で前と今の回転を Quaternion.Slerp して書く(Day 19 の描画の補間と同じ考え方)。補間した回転は「少し過去の髪」になる——1ステップ分(16.7ms)遅れる代わりに滑らかになる、という取引になることを確かめる。60 Hz の画面で確かめるには、StepSeconds を 1/20 にすると段が目で見える。

課題3(難): 鎖の途中に揺れないノードを挟む

今日残した歪みの1つ目。Joint に「1つ前の関節からこの関節までの間のノード」を覚えさせ、StepSpring で掛け進めるときに、間のノードのローカル行列(アニメーションの値)も順に掛ける。確かめるには、AvatarSample_A の髪の鎖を1つ飛ばしで読む(joints の偶数番だけを使う)ように Read を一時的に変える。直す前は髪の形が崩れ、直した後はファイルの形のまま揺れること。あわせて、ChildLocal(骨の長さと向き)も間のノードを通した位置にする必要がある。
