今日いちばん大事な3つ

1つ目は「キーの数字そのものには、動きの意味が無い」。VRMA のキーはファイルの骨のローカルの回転で、骨の休みの回転の上に掛ける値だ。three-vrm の見本 test.vrma(Blender で書いた)は 51 本の骨の休みの回転が全部ばらばらで、同じ「腕を下ろす」でも、休みの回転が単位のファイルとはまったく違う数字になる。上の実験台で「ファイルの休みの回転」を切り替えると、キーの値が変わる。

2つ目は「間に、世界にそろえた物差しを1つ挟む」。キーを一度正規化された回転(休みの姿勢からどれだけ回ったかを、世界にそろえた向きで書いたもの)に直し、アバターの休みの回転で戻す。

csharp
// VrmAnimation.CreateClip(Day 71)。three-vrm の VRMAnimationLoaderPlugin と VRMHumanoidRig を1本にした形
正規化   N = P x q x C^-1          // P, C = ファイルの「祖先の骨」と「この骨」の休みの世界の回転
戻す     r = W^-1 x N x W x R      // W = アバターの親ノードの休みの世界の回転、R = 骨の休みのローカルの回転

3つ目は「写すのは読み込みのとき1回」。両側から決まった回転を掛けるだけなので、キーを写してから補間しても、補間してから写しても同じになる。だからキーを1回だけ写した AnimationClip を作れば、再生・ブレンド・クロスフェードは Day 41〜42 の道をそのまま通る。AnimationPlayer は VRMA のことを何も知らない。

理論の要点

1. VRMA は「描くものの無い glTF」で、拡張は名札だけ

VRMA の中身は、骨の木(T ポーズ)と普通の glTF のアニメーション。拡張 VRMC_vrm_animation は「どのノードが何か」を書くだけで、動きそのものは全部チャンネルのキーにある。

動き拡張が名指すものチャンネル読み方
体humanoid.humanBones(骨の名前 → ノード)回転(hips だけは移動も)正規化してアバターの骨へ写す(要点2〜4)
表情expressions.preset / custom(表情の名前 → ノード)移動translation.x がそのまま重み。y と z は使わない(要点5)
視線lookAt.node回転+Z を回した向きから yaw と pitch(要点6)

メッシュを1つも持たないので、Day 32 からの GltfLoader.Load は「描けるメッシュが1つもありません」で止まる。そこでノードの木とアニメーションの段だけを通る口(GltfLoader.LoadAnimations)を開けた。GL に触らないので、窓を開く前でも、自己チェックからでも読める。

2. 休みの回転がそろっていない — 正規化

骨のローカルの回転は「親から見た向き」で、休みの姿勢でも単位とは限らない。Blender は骨の +Y を骨の伸びる向きに合わせるので、横へ伸びる腕の骨は休みの姿勢で 90 度回っている。VRoid の AvatarSample_A も、腰が 7.2 度、目の骨が 23.1 度傾いた休みの回転を持つ。

正規化された回転は、休みの姿勢からどれだけ回ったかを、世界にそろえた向きで書いたものだ。骨の世界の回転を「回り方 x 休みの世界の回転」に分けたときの「回り方」で、正規化された骨の木では、親子が順に掛け合わさる(世界 = 親の回り方 x 子の回り方 x 休みの世界)。

正規化の式 N = P x q x C^-1 の P はいちばん近い祖先の骨の休みの世界の回転、C はこの骨の休みの世界の回転(拡大は見ない)。親が骨のとき休みの姿勢のキーは q = P^-1 x C なので、N は単位になる(自己チェック1)。間に骨でないノードが挟まっていても祖先の骨まで登るのは、正規化された骨の木が骨だけでできているから。

実験台で「キーをそのまま」にして、ファイルの休みの回転を切り替えると、ずれの大きさが変わる。ファイルが UniVRM 流(単位)でもずれるのは、アバターの休みの回転(ここでは腰の傾き)のほうも単位でないから。実機では test.vrma をそのまま当てると最大 77.7 度、honya-wave でも最大 11.9 度ずれる(自己チェック11)。

3. アバターへ戻す — 同じ式を、反対向きに

正規化された回転を、アバターの骨のローカルの回転へ戻す。

csharp
// VrmAnimation.Denormalize。three-vrm の VRMHumanoidRig.update と同じ式
public static Quaternion Denormalize(Quaternion normalized, Quaternion parentRestWorld, Quaternion restLocal) =>
    Quaternion.Inverse(parentRestWorld) * normalized * parentRestWorld * restLocal;
  • W^-1 x N x W は「世界にそろえた向きの回り方 N を、親の休みの向きから見直したもの」。それを骨の休みの回転 R の上に掛ける
  • W はアバターの親ノード(骨とは限らない)の休みの世界の回転。親が回り方 N親 で動いていれば、骨の世界の回転は N親 x W x W^-1 x N x W x R = N親 x N x (W x R) になり、正規化された木の掛け算とそろう(自己チェック2)
  • System.Numerics の Quaternion の * はハミルトン積で、右を先に回す(a * b は b のあとに a)。行列(行ベクトル規約)の Ma * Mb とは並びが逆になる。AnimationPlayer の local * _world[parent] は、クォータニオンなら 親 * local

キーごとの写しは A x q x B で、補間とぶつからない。両側から決まった回転を掛けるのは球面の上の距離を変えないので、2つのキーの間の slerp の道筋がそのまま写る。だから AnimationClip.Sampler.Map でキーを1回写せば、あとは Day 41 の SampleRotation がそのまま使える。

実機の自己チェック10 は、ファイルの骨の木も AnimationPlayer で同じ時刻まで流し、両方にある骨の「回り方」を比べる。test.vrma(Blender 流)でも honya-wave(UniVRM 流)でも、8 つの時刻のずれの最大は 0.000 度(ファイルの骨は最大 60.0 度・118.4 度回っている)。

4. 腰の移動 — 背丈の比で縮める

移動のキーを持ってよいのは hips だけ(仕様)。腰の移動は「hips の親から見た位置」なので、ファイルの hips の親の休みの世界の行列で世界の位置にし、アバターの腰の高さ ÷ ファイルの腰の高さで縮めてから、アバターの hips の親の座標へ戻す。

クリップファイルの腰の高さAvatarSample_A の腰の高さ比縮めないと
honya-wave1.000m0.895m0.8954腰が 10.4cm 上がり、足が床から浮く(自己チェック12)
test0.850m0.895m1.053test は腰の移動を持たないので変わらない

ほかの骨の移動は捨てる(仕様で禁止。背丈の違うアバターに当てると、腕が伸び縮みする)。骨の長さはアバターのまま、回り方だけを写すのがヒューマノイドのリターゲットの基本形だ。

5. 表情 — translation.x がそのまま重み

表情ごとのノードの移動の x 成分を、同じ名前の表情の重みとして読む(VrmAnimation.SampleExpression)。重みは 0〜1 に収める(仕様。範囲の外の値を受け取ったら、実装が収める)。表情の名前はプリセットなら約束があるので(Day 69 の要点)、どのアバターにも同じ呼び方で書ける。

  • キーを持たない表情には触らない。test は happy しか持たないので、まばたき(Day 69 の自動まばたき)も口も、メニューの選択のまま動き続ける
  • VRMA の表情は最後に書く(UpdateVrmFace の、自動まばたきの行の後ろ)。メニューの重みを寄せる Fade より前に書くと、寄せる途中で VRMA の値が目標の値へ引き戻される
  • クリップを混ぜている間は、表情も体と同じ重みで混ぜる。片方のクリップにしか無い表情は、無いほうを 0 として混ぜる(出ていくクリップの笑顔は、出ていくのに合わせて消える)
  • 表情は体と同じクリップの時刻で読む(AnimationPlayer.ClipTime を開けた)。だから体を先に進め(UpdateVrmAnimation)、そのあとで表情を書く

6. 視線 — yaw と pitch、rangeMap、内と外

視線ノードの回転で +Z を回し、その向きから yaw(Y まわり。左 = +X が正)と pitch(上が正)を出す。仕様の「Extrinsic ZXY」(Y → X の順のオイラー角)と同じで、Z まわりは捨てる。

見たい角度をそのまま目に渡さない。目の玉は顔の中で 10 度ほどしか回らず、それ以上回すと瞳が顔の外へ出る(白目をむく)。そこで rangeMap で縮める。

表(AvatarSample_A の値)使う場面見たい角度 → 目の角度
rangeMapHorizontalOuter(90 → 12)左を見るときの左目、右を見るときの右目(外へ)45 度 → 6 度、90 度以上 → 12 度
rangeMapHorizontalInner(90 → 8)左を見るときの右目、右を見るときの左目(鼻の側へ)45 度 → 4 度
rangeMapVerticalUp / Down(90 → 10)上下(両目同じ)45 度 → 5 度

決めた角度は、目の骨の正規化された回転(Y まわり yaw・X まわり pitch)として Denormalize で戻す。AvatarSample_A の目の骨は休みの回転が 23.1 度傾いているので、ローカルの回転に直接 yaw を掛けると斜めに回る(自己チェック5 が、世界の向きで左目 6.00 度・右目 4.00 度になることを確かめる)。

「カメラを見る」(F6)は、目の位置(頭の骨から offsetFromHeadBone = 6cm 上)からカメラへの向きを、休みの頭の向きで測る。首を振っていても(「VRMの揺れもの」の F2)、目は振った首を打ち消すように回る。

7. クリップの切り替え — 位相同期を切る

切り替えは Day 42 の SetBlend(重みを付けて2本を混ぜる)そのもので、0.3 秒かけて出ていくクリップの重みを 1 → 0、入ってくるクリップの重みを 0 → 1 にする(VrmAvatar.UpdateAnimation)。違うのは位相同期を切ること。

  • Day 42 の歩きと走りは、長さの違う2本を「1周のどこか」(位相)でそろえて混ぜた。足の運びが同じ動きだから成り立つ
  • VRMA どうしは別々の動き。位相をそろえると、入ってくるクリップが頭からではなく、出ていくクリップと同じ割合の位置から始まってしまう

今日残した歪み

1つ目: アバターに無い骨のキーは捨てる。VRMA が upperChest を回していて、アバターが upperChest を持たないと、その回転が失われる(胸から上が少し起き上がった姿勢になる)。AvatarSample_A は VRM の骨を 54 本持ち(無いのは顎の jaw だけ)、今日の2本のキーの骨は全部そろっているので表に出ない。直すなら改造課題3。

2つ目: いつもループする。AnimationPlayer は剰余で折り返すので、7種セットのような見せ用の1回きりの動きも頭から繰り返す。Day 72 でエモートにするときは「1回流して最後の姿勢で止める」が要る(改造課題2)。

3つ目: 「止める」は混ぜない。SetBlend は重みを合計 1 に正規化するので、「クリップ 0.3 + 何もない 0.7」が作れない。止めると T ポーズへ1フレームで戻る。

4つ目: 視線は bone 型だけ。VrmLookAt は表情を知らないので、expression 型(瞳の絵を lookLeft などの重みで動かすアバター)は目が動かない。AvatarSample_A は bone 型。

5つ目: 腰の縮尺は腰の高さの比だけ。脚の長さの比ではないので、脚の短いアバターに大股のクリップを当てると足が滑る。Day 72 の移動のクリップで向き合う。

試して分かったこと

  • 正規化が要るのは、ファイルが変だからではない。休みの回転が全部単位の honya-wave でも、キーをそのまま当てると最大 11.9 度ずれる。アバター側(腰 7.2 度など)の休みの回転も単位でないから。両側をそろえる物差しが要る
  • 目の骨にも同じ式が要る。AvatarSample_A の目の骨は休みの回転が 23.1 度傾いていて、ローカルに yaw を掛けると斜め下へ回った。正規化された回転として Denormalize で戻したら、世界の向きで 6.00 度 / 4.00 度ちょうどになった
  • 位相同期が既定で ON(Day 42)。そのまま切り替えると、test が頭ではなく honya-wave と同じ割合の位置から始まった。VRMA どうしの切り替えには合わない
  • 切り替えを混ぜても、髪の揺れはほとんど変わらない。即座だと右の上腕が 1 フレームで 78.3 度飛ぶ(混ぜると 9.8 度)が、髪の先端の速さはどちらも 75cm/s 前後。test の腕の振りそのもの(0.5 秒で 90 度)に振られている
  • VRMA は軽い。読み込みは1本 0.5〜0.7ms、写したあとは Day 41 の再生と同じ値段

改造課題

課題1(易): カメラを見るとき、首も少し回す

目だけでは 12 度しか回らないので、横から見ると目線が届いていない。「カメラを見る」のとき、見たい角度の 30% を頭の骨に回す。頭の骨の回転も正規化された回転として作り、VrmAnimation.Denormalize で戻す(Y まわりに yaw x 0.3)。目に渡す角度は残りの 70% にする。ApplyVrmGaze の中で、目より先に頭を書き、UpdateWorldAndJoints を挟んでから目の角度を測ること(要点6の「休みの頭の向きで測る」が、首を回したぶんを差し引いてくれる)。

課題2(中): 1回だけ流して、最後の姿勢で止める

今日残した歪みの2つ目。AnimationPlayer に Loop(既定 true)を足し、false なら Advance の Wrap の代わりに Math.Clamp(time, 0, duration) で止める。VrmAvatar.Play に loop の引数を足し、止まったら(時刻が長さに届いたら)前のクリップへ混ぜて戻す、まで作ると、Day 72 のエモートの形になる。位相同期を切ってあるので、クリップごとの時刻(_clipTimes)のほうを止めればよい。

課題3(難): アバターに無い骨のキーを、子の骨へ寄せる

今日残した歪みの1つ目。VRMA に upperChest のキーがあり、アバターに upperChest が無いとき、正規化された回転 NupperChest を、アバターにある子の骨(neck・leftShoulder・rightShoulder)の正規化された回転の左から掛ける(Nneck' = NupperChest x Nneck)。子の骨にキーが無ければ、upperChest のキーをそのまま子のキーにする。キーの時刻が骨ごとに違うときは、両方の時刻を合わせた表を作り直す必要がある。確かめるには、make_honya_wave.py に upperChest のキーを足し、VrmAvatar.HumanBones から一時的に upperChest を外して読み、自己チェック10 のずれが 0 に戻ることを見る。

検証の途中で分かったこと

  • ファイルの骨の木も AnimationPlayer で流せる。LoadAnimations で読んだノードとクリップから GL を持たない Model を作れば(Day 70 の振り子の台と同じ形)、ファイルの側の「正解の動き」が同じ物差しで取れる。自己チェック10・11 はこれで比べた
  • three-vrm の bone 型の視線は、上を見るときに rangeMapVerticalDown を引いているように読める(pitch の符号の取り方)。AvatarSample_A は上下とも 10 度なので結果は同じ。今日は名前どおり、上を見るときに Up を使った
  • 7種セットはリポジトリに入れられないので、見本は three-vrm の test.vrma(MIT)と、スクリプトで作った honya-wave.vrma(CC0)にした。test.vrma は Blender 流、honya-wave は UniVRM 流と、休みの回転の書き方が両極端なので、正規化の見比べにはむしろ都合がよかった
  • コンソールに「〜」を出すと化ける(CP932)。表示の文字列では使わない(Day 69・70 と同じ)
