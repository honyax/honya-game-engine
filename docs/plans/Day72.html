今日いちばん大事な3つ

1つ目は「MToon は後処理なしで見る約束で作られている」。MToon は N・L を掛けず、明るい側に「ベースカラー x 光の色」をそのまま置く。光 1 で照らせば、明るい側はベースカラーの絵の画素の値そのものになる。そこへ ACES を通すと、白(1.0)は 0.80(画面で 231)に沈み、18% のグレーは 0.27 へ持ち上がる。上の実験台で「白い服」を選び、光 1・環境光 0 にすると、キャラの出口は 255、シーンの出口は 231 になる。

2つ目は「分けるのは出口だけ」。キャラを後処理のあとで描き足すと TAA も被写界深度も掛からず、ずらしで輪郭が震え、壁の陰との深度も合わない。キャラは今までどおりシーンのバッファに描き、どの画素がキャラかの印(割合)をアルファに書いて出口まで運ぶ。出口は印の割合だけ、ACES の代わりに「1 で切って sRGB」を使う。

glsl
// composite.frag(Day 72)。割合 0 の画素は Day 71 と1行も変わらない
vec3 display = LinearToSrgb(Aces(露出 x シーン + ブルーム));                  // シーンの出口(今まで)
vec3 character = LinearToSrgbExact(clamp(露出 x シーン, 0, 1));               // キャラの出口(今日)
display = mix(display, character, 割合);                                     // 画面の値の上で重ねる

3つ目は「印も TAA で均す」。キャラは毎フレーム1画素未満ずらして描かれるので、輪郭の画素の割合は 0 と 1 を行き来する。色だけ TAA で混ぜて割合を今のフレームのまま出口へ渡すと、同じ「混ざった色」に ACES と表示の色を交互に掛けることになり、輪郭がちらつく。割合を色と同じ重みで混ぜれば、割合も「この画素のうちキャラが占める面積」に落ち着く(実験台「割合の運び方」)。

理論の要点

1. MToon の約束と、ACES が白と色にすること

MToon の明るい側は ベースカラー x 光の色(N・L を掛けない)。作者は「白い平行光 1 + 環境光わずか」で、トーンマップ無しの画面を見て色を決める。だから光 1 で照らした明るい側は、ベースカラーの絵の画素の値で画面に出るのが正解になる。Day 31 からの出口は、そこへ3つのことをする。

出口の段キャラに起きること数字(式・実機)
ブルーム(しきい値 1.0)1 を超えた白い服と肌がにじむ床の上の光(白 1.0 + 空 1/4)で、キャラの画素の 44.8% が 1 を超える(いちばん明るい成分 1.34)
ACES白が灰色に寄る1.0 → 0.804(画面で 231)。255 に届くのはリニアで 7.25 を超えてから
ACES中間が持ち上がり、色が浅くなる18% のグレー → 0.267。赤茶 (0.60, 0.25, 0.18) の彩度(画面の値で (最大 − 最小) / 最大)が 42% → 34%

ACES はチャンネルごとに同じ曲線を掛ける。明るいところで曲線が寝るので、明るいチャンネルほど押し下げられ、暗いチャンネルは持ち上がる。チャンネルどうしの差が縮むので、色が浅くなる。写実のシーンではそれが「フィルムらしさ」になるが、セルルックでは塗った色が変わることになる。

上の実験台で「肌」を選び、環境光を 0.25 にすると、シーンの出口は白っぽい肌になる(実機の F3 の左半分と同じ)。キャラの出口でも 1 を超えたチャンネルは切れるので、肌の赤みは少し飛ぶ——床の上の光は MToon の約束(光 1・環境光わずか)より明るい(検証の途中で分かったこと)。

2. どこでキャラを分けるか — 出口だけを変える

シーンとキャラで違うのは出口の曲線だけ。ずらし・履歴・深度・速度・ぼけは、同じ場所に立っている物として同じに扱いたい。

分け方TAA被写界深度・モーションブラー出口
A. キャラを後処理のあとで描き足す掛からない。ずらしたまま描くと輪郭が震え、ずらさずに描くとシーンの深度と半画素ずれる掛からない(裏通りのボケの中で、キャラだけくっきり)思いどおり
B. 逆トーンマップで HDR に埋める(出口で元に戻る値を書く)掛かる掛かる白は 7.25 で書くことになり、ブルームが真っ白に光る。輪郭で背景と混ぜると、7.25 が平均に勝って明るい縁が出る
C. 今日: 割合をアルファで運び、出口で分ける掛かる(割合も一緒に混ぜる)掛かる(割合は素通し)割合の分だけキャラの出口

C の代わりに払うのは、後処理の段がアルファを運ぶ約束を守ること。Day 31 から、どの段もアルファに 1 を書いて捨てていた。今日、TAA・被写界深度の重ね・モーションブラーの3段が、出す画素のアルファに入口の割合を入れるようになった(要点4)。

3. 割合をアルファに書く — 書くのはキャラだけ

シーンを描くシェーダ(textured.frag・deferred.frag・空…)は、どれもアルファに 1 を書いている。だから「キャラが書いたら 1」では区別できない。順番で区別する。

  1. キャラの直前に、アルファだけを 0 に消す(PostProcess.BeginCharacter。glColorMask(false, false, false, true) にして glClear)。色と深度は残る
  2. キャラを描く。不透明・MASK・線は 1 を書く。深度に負けた画素(壁の陰)は 0 のまま
  3. アルファへの書き込みを閉じる(PostProcess.EndCharacter。glColorMask(true, true, true, false))。このあとの粒・プローブの球・文字は色だけを書く
  4. 後処理の頭で開け直す(EndCore)。TAA の履歴や被写界深度の層はアルファも書くので

半透明(瞳・ハイライト・眉)は色と同じ混ぜ方のままだと、アルファが a x a + 下 x (1 − a) になる。髪の上に乗った眉は下が 1 なので 1 のままだが、シーンの上に直接乗った半透明の端は a x a に薄まる。そこでアルファだけ混ぜ方を変える(glBlendFuncSeparate の後ろ2つを One, OneMinusSrcAlpha)。膜を1枚重ねた分だけキャラが増える、という「割合」の足し算になる。

もう1つの約束: キャラを描いたフレームだけ、出口がアルファを見る(PostProcess.CharacterDrawn。Begin で下ろし、EndCharacter で立てる)。描かないフレームのアルファは 1 だらけなので、見たら画面全体がキャラになる。自己チェックが後処理だけを回すときも、これで Day 31〜71 の数字が変わらない。

4. TAA は割合も混ぜ、ぼかしは素通しにする

TAA は「今のフレームを 1 割、履歴を 9 割」で混ぜ続ける(Day 54)。キャラの割合も同じ重みで混ぜる。

glsl
// taa.frag(Day 72)の最後。色の箱とは別に、近所 3x3 の割合の最小〜最大を取ってある
float historyCoverage = texture(uHistory, historyUv).a;           // 双線形(Catmull-Rom の負の重みで 0〜1 をはみ出させない)
if (uRectify != 0)
{
    historyCoverage = clamp(historyCoverage, coverageMin, coverageMax);   // 立ち去った画素に割合を残さない
}

float coverage = mix(historyCoverage, currentCoverage, uCurrentWeight);
  • 疑うのは、キャラが動いて立ち去った画素に割合が残ると、背景が「1 で切る」出口を通ってしまうから。止まった絵の輪郭は、近所に 0 と 1 の両方があるので箱が [0, 1] になり、履歴がそのまま生きる
  • 速度・疑った量の表示(uDebug 2・3)はアルファに 0 を書く。表示用の絵をキャラの出口へ通さないため
  • 自己チェック8: 割合 1 の次に割合 0 を解くと、疑わなければ 0.900、分散で疑えば 0.000。色は 0.200 のまま

被写界深度(dof-combine.frag)とモーションブラー(motion-blur.frag)は、入口の画素の割合を素通しにする。被写界深度の半分の大きさの層は、アルファを「錯乱円」と「覆い」に使っていて、割合を運ぶ席が無い。ぼけたキャラの輪郭のはみ出しはシーンの出口を通る(今日残した歪みの1つ目)。

5. 出口: ブルームから外し、1 で切って sRGB で出す

明部の抽出(bright.frag)は、抜く重みに 1 − 割合 を掛ける。キャラの画素はにじみの元にならない。合成(composite.frag)はキャラの出口を別に作って、画面の値の上で割合どおりに重ねる。

段シーンの出口(今まで)キャラの出口(今日)なぜ
露出掛ける掛ける同じカメラで撮った絵。夜の裏通りで露出 1.30 なら、キャラも 1.30 倍で写る(自己チェック6)
ブルーム足す足さない・元にもしないthree-vrm の既定に無い。白い服が光らない(自己チェック7)
グレーディング掛ける掛ける夕焼けの色かぶりはキャラにも乗ってほしい。既定はニュートラル(素通し)
トーンマップACES0〜1 で切るMToon の約束(光 1 で明るい側 = ベースカラー)のまま出す
符号化ガンマ 2.2sRGB の式テクスチャを戻した式の逆。光 1 の明るい側が、絵の画素の値のまま出る(要点6)

重ねるのは符号化のあと。キャラは「表示の色で描いた層」なので、画面の値の上で重ねる(割合 0.5 なら、2本の出口の真ん中。自己チェック5)。リニアの値で重ねると、片方を ACES、片方を 1 で切ったものを足すことになり、どちらの曲線とも違う値が輪郭に出る。

6. three-vrm と突き合わせる — 同じ光、同じ符号化

three.js の出口は既定で NoToneMapping + sRGB。テクスチャは GPU が sRGB の式でリニアへ戻すので(Day 31 から Srgb8Alpha8)、出口も同じ式の逆で符号化すれば、光 1 の明るい側は絵の画素の値に戻る。

出口(割合 1)sRGB の 256 段をリニアに戻して置き、8bit で読み返す(自己チェック3)
sRGB の式(今日)256/256 段が一致
ガンマ 2.2(シーンの出口の符号化)最大 9 段ずれる(画素 7 が 16 に。暗いほど持ち上がる。白と中間はほぼ同じ)
ACES + ガンマ 2.2(Day 71)最大 27 段ずれる

光も合わせる。three-vrm の見本(examples/dnd.html)は、位置 (1, 1, 1) から原点へ向かう白の平行光(three.js の強さ π は、物理の単位で「1」)1本だけで、環境光が無い。F6 でこの光にする(VrmThreeLightDirection・空を 0)。カメラは画角 60 度のまま、見本(画角 30 度・5m)と同じ高さが写る距離まで寄せる(5 x tan 15 度 / tan 30 度 = 2.3m)。

この光で数えると、キャラの画素のいちばん明るい成分は 1.00(1 を超える画素は 25 個だけ)。MToon の約束どおり、明るい側がベースカラーで頭打ちになる。床の上の光(空 1/4)の 1.34 と比べると、Day 68 の光がまだ約束より明るいことも分かる。

キャラを分ける場所の3案

要点2の表のとおり、分けるのは出口だけにした。決め手は TAA で、キャラだけ TAA を外すと、ずらしたままの輪郭が毎フレーム震えるか(ずらして描く)、シーンの深度と半画素ずれる(ずらさずに描く)。被写界深度も、裏通りでキャラだけくっきり浮く。どちらも「同じ場所に立っていない」絵になる。

代わりに、印を出口まで運ぶことが要る。印の運び手は「色と一緒に混ぜる段」と「素通しにする段」に分かれる。

今日残した歪み

1つ目: 被写界深度とモーションブラーは割合を運ばない。ぼけた輪郭のはみ出し(キャラの色が背景側へ広がった所)は割合 0 なのでシーンの出口を通り、割合 1 の内側とのあいだに薄い段差が出うる。裏通りの決めの構図ではキャラにピントが合っているので見えない。直すなら改造課題3。

2つ目: キャラの手前に描かれた物は、キャラの出口を通る。粒・プローブの球・SDF はアルファを閉じたあとに描くので、キャラの上に重なった画素の割合は 1 のまま。加算の火の粉がキャラの前を横切ると、ACES で畳まれずに 1 で切れる。直すなら改造課題2。

3つ目: 床の上の光は MToon の約束より明るい。Day 68 で決めた「白 1.0 + 空 1/4」では、キャラの画素の 44.8% が 1 を超えて切れる(肌の赤みが少し飛ぶ)。three-vrm の光(F6)なら最大 1.00。床の上の光を変えると Day 68〜71 の絵と計画書の数字が全部変わるので、今日は変えなかった。

4つ目: 出口の符号化が2つある。シーンはガンマ 2.2、キャラは sRGB の式。シーンも sRGB の式にするのが筋だが、Day 31 からの絵と自己チェックの数字が全部動くので、キャラの側だけ正しくした(F5 でキャラもガンマ 2.2 にできる)。

5つ目: シーンのブルームはキャラの上に乗らない。街灯のにじみは、キャラの輪郭で止まる(割合 1 の画素はシーンの出口の値を捨てる)。写実のレンズのにじみなら手前の物にも掛かるが、three-vrm の既定に合わせた。

改造課題

課題1(易): キャラの出口に「白の上限」を足す

床の上の光では、キャラの画素の 45% が 1 を超えて切れる(歪みの3つ目)。PostProcess に CharacterWhite(既定 1.0)を足し、composite.frag のキャラの出口で character / uCharacterWhite にしてから切る。1.34 にすると床の上で白い服が切れなくなる代わりに、three-vrm の光では全体が暗くなる——「光を約束どおりにする」のと「出口で合わせる」のどちらが筋かを、F6 で見比べて考える。

課題2(中): 手前の粒にはシーンの出口を通す

歪みの2つ目。粒(RenderParticles)を描く間だけアルファを開け、粒のブレンドを BlendFuncSeparate にして、アルファ側を「下の割合 x (1 − 粒の覆い)」(Zero, OneMinusSrcAlpha)にする。加算の粒(SrcAlpha, One)は覆いを持たないので、明るさから覆いを作る(たとえば min(1, 粒の明るさ) をアルファに出す)。F7 の裏通りで「VFX」の粒をキャラの前に出して、ACES で畳まれるかを確かめる。

課題3(難): 被写界深度にも割合を運ぶ

歪みの1つ目。被写界深度の半分の大きさの層(DepthOfField の _layers)に3枚目(R8 か R16F)を足し、dof-gather.frag で奥の層・手前の層と同じ重みで割合を集め、dof-combine.frag で色と同じ式(mix(sharp, far, farAmount) と前掛けのアルファ)で重ねる。確かめるには、F7 の裏通りで FocusDistance をキャラより手前に寄せ、ぼけたキャラの輪郭が F4 で灰色にぼけること、F3 の右半分で輪郭に段差が出ないことを見る。

Windows 11 / .NET 10 / NVIDIA GeForce RTX 3070(OpenGL 4.3)、1920x1080、VSync あり(60 Hz)

確かめたこと: ビルド、dotnet format whitespace --verify-no-changes、自己チェック 8 項目(VRMビューアを出す前と後)、Day 31・38・54・55・68・71 の自己チェック、Day 48 の割り当て表(344 項目)、床の上の Day 71 との全画素の突き合わせ(出口を切って差 0)、床の上で見た絵(表示の色 / シーンと同じ / 左右に並べる / 顔に寄って並べる / three-vrm の光で両方 / ガンマ 2.2 / 割合を TAA と FXAA で / 露出 x2)、裏通りで見た絵(表示の色 / シーンと同じ / 割合)

検証の途中で分かったこと

  • 内訳を自己チェックの直後に押すと、自己チェックが書いた作り物の絵を数える(シーンのバッファを借りて帯を書くので)。次のフレームで描き直されるので、1フレーム空ければ正しい数字になる
  • three-vrm の dnd の見本は、カメラの画角が 30 度。こちらは 60 度のまま距離で合わせたので、遠近の付き方(腕の先の細り方)は少し違う。色を比べるには関係しない
  • ブラウザ拡張がつながっていなかったので、three-vrm 本体の画面は撮れなかった(完成条件2の囲み)。光と出口の約束を数字でそろえるところまでにした
  • コンソールに「〜」を出すと化ける(CP932)。自己チェックの文字列では「0 から 4」と書いた(Day 69〜71 と同じ)
