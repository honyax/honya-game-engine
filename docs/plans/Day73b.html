今日いちばん大事な3つ

1つ目は「速さはクリップが決め、カプセルがそれに従う」。Day 51 のキツネは、歩き 2.0・走り 5.0 m/s というゲームの側で決めた速さを、そのままブレンド木のしきい値にしていた(キツネのクリップは根の移動を持たず、足が滑らない速さを測れないから)。今日は向きが逆で、Day 73a で測った「足が滑らない速さ」(歩き 0.97・走り 2.36 m/s)を、カプセルの歩きと走りの速さにする。その速さちょうどで歩きだけ・走りだけが流れるので、足は床に止まる。

2つ目は「エモートは移動の上に重ねる層」。エモートを流している間も、移動の木は毎フレーム重みを決めている。その重みを (1 − e) 倍に縮め、空いた e をエモートが埋める。e は頭の 0.3 秒で 0 → 1、終わりの 0.3 秒で 1 → 0 になるので、移動からエモートへ・エモートから移動へ、どちらも混ぜながら移る。

csharp
// VrmAvatar.PlayBlend(Day 73b)
e        = EmoteEnvelope(エモートの時刻, 長さ, 0.3)        // 0 → 1 → 1 → 0
重み     = 移動の重み x (1 - e) + エモート x e               // LayerEmote。合計は 1 のまま
Animation.SetOwnTime(エモート, true)                         // エモートだけ位相の外で、自分の頭から流す

3つ目は「エモートだけ位相の外に出す」。移動のクリップは位相を合わせて混ぜている(Day 42)。同じプレイヤーにエモートを足すと、エモートも「位相 x 長さ」の時刻で読まれ、頭から流れない(手を振る途中から始まる)。位相合わせを丸ごと切ると、今度は歩きと走りの足がずれる。そこで AnimationPlayer に「このクリップだけは自分の時刻で回し、周期にも数えない」という口(SetOwnTime)を開けた。

理論の要点

1. 差し替えるのは「置き場所」と「カプセル」だけ

Day 51 のデモは、カプセル(当たり判定)とモデル(見た目)が別物という作りだった。2つを結ぶのは「足元と向きから世界行列を作る」「速さを木に渡す」「モデルの寸法をカプセルに合わせる」の3本だけで、逆向きの矢印は無い。だから差し替えるのも、この3本の相手だけでよい。

結ぶ道Day 51(キツネ)Day 73b(VRM)
置くPlayableDemo.Transform = 足元合わせ x 倍率 x 向き x 位置VrmPlacement = 足元合わせ x 向き x 位置(VRM は m で書かれているので倍率は無い)
混ぜるカプセルの速さ → キツネの木(しきい値 2.0 / 5.0)カプセルの速さ → 73a の木(しきい値 0.97 / 2.36)。カプセルの速さもこのしきい値(要点2)
合わせる今のポーズの箱から全高 0.70m・半径 0.19midle の姿勢の箱から全高 1.564m・半径 0.138m

寸法は idle の姿勢で測る(Day 51 の「今のポーズで測る」と同じ理由)。VRM 1.0 は T ポーズで書き出すので、ファイルの箱は腕を広げた横幅 1.37m を持つ。腕を下ろした idle なら 0.51m で、足元の水平の中心も体の真ん中になる。測るのは別の AnimationPlayer で、表示中の姿勢には触らない。

VRM 1.0 の正面は +Z で、CharacterController.FacingYaw も「+Z を Y まわりに回した向き」(速度から atan2(x, z))なので、向きはそのまま渡せる。

2. 速さの向きが逆になる — カプセルがクリップに従う

Day 51(キツネ)Day 73b(VRM)
先に決まるものゲームの速さ(歩き 2.0・走り 5.0 m/s)クリップの速さ(73a で根の移動から測った 0.97・2.36 m/s)
後から合わせるもの木のしきい値カプセルの歩きと走りの速さ
なぜそうするかキツネのクリップは根の移動を持たず、足が滑らない速さを測れない測れるので、測った速さで運べば足が滑らない

F6 で「キツネの速さ」にすると、カプセルは歩き 2.0・走り 5.0 m/s で進むのに、クリップは同じ歩幅のまま。歩きは木の上で走りと混ざって速歩きのように見え、走りはクリップの倍以上の速さで足が滑る(自己チェックで走りの足の滑りが -0.11 → 2.53 m/s)。

3. エモートは移動の上に重ねる

エモートの間も、移動の木は毎フレーム重みを出している。エモートの重みを e として、移動の重みを (1 − e) 倍に縮め、エモートを e で足す(VrmAvatar.LayerEmote)。合計は 1 のままなので、SetBlend がもう一度正規化しても何も変わらない。

  • 重みの形(EmoteEnvelope)は、頭の 0.3 秒で 0 → 1、終わりの 0.3 秒で 1 → 0。抜け終わるのがちょうどクリップの終わりなので、AnimationPlayer がループの頭へ折り返す1フレームは重み 0 で見えない。VRMA はいつもループする(Day 71 の今日残した歪み2)が、それを直さずに「1回だけ流す」が作れた
  • 途中でやめる(StopEmote)ときは、いまの重みから同じ速さ(0.3 秒で 1)で下げる。いきなり 0 にすると、挙げた腕が1フレームで下りる
  • 表情も同じ重みで混ざる。Day 71 の ApplyClipFace は、混ぜているクリップの重みで表情を足し合わせるので、エモートが抜けていく間に笑顔も一緒に消える(コードは1行も足していない)

エモートは立ち止まっているときだけ出し、動き出したらやめる(速さ 0.3 m/s が境目)。VRoid の7種セットは体じゅう 52 本の骨のキーを持つので、歩きながら重ねると、エモートの重みの分だけ脚が歩きをやめ、カプセルだけが進んで足が滑る。上半身だけに重ねる(骨ごとのマスク)なら歩きながら手を振れるが、今日は作らない(改造課題3)。

4. エモートだけ位相の外で回す

Day 42 の位相合わせは、混ぜているクリップ全部を「同じ 1 周のどこか」で読む。周期は重みで混ぜた長さ(Duration)で、時刻は 位相 x そのクリップの長さ。歩きと走りにはこれが要る。ところがエモートを同じ表に足すと、2つ壊れる。

  1. エモートが頭から流れない。読む時刻が「位相 x 4 秒」になり、エモートを始めた瞬間の位相(0〜1 のどこか)から始まる
  2. 歩調が変わる。周期にエモートの長さが混ざり、歩き 0.25 + 走り 0.25 + エモート 0.5 なら 0.90 秒が 2.45 秒に伸びる(エモートが入ってくる間だけ、脚がゆっくりになる)

Day 71 の VRMA の切り替えは、位相合わせを丸ごと切って避けた(SyncPhase = false)。今日は歩きと走りの位相は合わせたまま、エモートだけを外に出したいので、AnimationPlayer.SetOwnTime(clip, true) を開けた。外に出したクリップはクリップごとの時刻(Day 71 の _clipTimes)で読み、周期にも数えない。RestartClip で頭へ戻せる。

5. 入力は表を通す — E の横取り

エモートの合図はキーのイベントで直に出さず、入力の表(InputMap)に GameAction.Emote を足し、固定ステップが InputSnapshot 越しに読む(Day 18 の要点2、Day 45 のジャンプと同じ)。こうしておくと、Day 19 の入力の録画と再生(M / N)にもエモートが乗る。

E は「実演用のテクスチャを同期で読む」に埋まっているので、Space(一時停止とジャンプ)と同じく、OnKeyDown が VRM のキャラで遊んでいる間だけ E を飲み込む。固定ステップは「押された」の印(_vrmEmoteRequested)を立てるだけで、エモートを流すのは可変 dt のアニメーションの側。押した瞬間は1ステップにしか乗らないので、印にして渡す。

6. クレジットと、カメラの構え

クレジットは HUD を消しても出す。7種セットの利用条件で、流している間の表記が必須。Day 71 は HUD の1行に出していたが、HUD(; で切り替える文字の表示)を消すと1文字も出なくなる。今日は、VRoid のクリップの重みが 0 より大きい間(入ってくる途中・抜ける途中も含む)、HUD とは別に画面の左下へ描く(DrawVrmCredit)。VRMビューアの床の上でも同じ。

追従カメラの構えはキャラの全高に比例させる。Day 51 の肩越しの構え(中: 距離 2.8m・注視点の高さ 0.52m)は 70cm のキツネに合わせた値で、1.56m の VRM にそのまま使うと、注視点が腰より低く、頭が画面の上から切れた。距離と高さに「全高 / キツネの全高」(2.23)を掛ければ、どのキャラでも同じ構図になる(仰角は比に関係しない)。

  • カメラの構えはキツネの寸法だった。最初に VRM を立たせたら、追従カメラが近すぎて頭が画面の上から切れた。Day 51 の構えの表は 70cm のキツネに合わせた値で、全高の比を掛けたら Day 51 と同じ構図になった(距離 2.8m → 6.25m)。キツネに戻すと比は 1 で、Day 51 の絵のまま

  • キツネと VRM の差し替えは、カプセルの寸法と構えを合わせ直すだけで済んだ。世界(環境の当たり判定)を組み直さず、居る場所もそのまま

改造課題

課題1(易): エモートを Q で選び直す

いまは F4(メニュー)で選ぶ。GameAction.EmoteNext を足して Q に割り当て、UpdateCharacter で印を立て、UpdateVrmPlayable で VrmEmoteCandidates の次へ進める。Q も「実演用のテクスチャを非同期で読む」に埋まっているので、E と同じく OnKeyDown で横取りする。入力の録画(M)と再生(N)で、選び直しまで再現されることを確かめる。

課題2(中): 跳んでいる間は idle の上に「跳び」のポーズを重ねる

今日残した歪みの1つ目。Mixamo の Jump(か、腰を少し沈めて膝を曲げた1コマのポーズを make_honya_locomotion.py で作ったもの)を assets/mixamo/ に足して読み、Character.IsGrounded が false の間だけ、エモートと同じ重ね方(LayerEmote)で 0.15 秒で入れて、着地で抜く。重ねる仕組みは今日のエモートの層がそのまま使える(ただしエモートと同時には重ねられないので、層を2本にするか、跳んでいる間はエモートをやめる)。

課題3(難): 歩きながら手を振る — 骨ごとのマスク

今日残した歪みの4つ目。エモートの重みを骨ごとに変える。AnimationPlayer.Evaluate は「クリップごとに全部のノードへ同じ重み」で足し込んでいるので、SetBlend とは別に「クリップ i を、ノード n には重み x m[n] で足す」マスクの表を渡せるようにする。マスクは spine から上(chest・upperChest・neck・head・両腕と指)を 1、腰と脚を 0。腰の回転を 0 にすると、エモートの上半身のひねりが腰の向きに付いてこないので、spine だけ 0.5 にするとつながりが自然になる。歩きながら honya-wave を流し、脚は歩き・腕は手を振るになれば完成。そのうえで「動いたらやめる」を外す。
