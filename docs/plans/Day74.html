今日いちばん大事な3つ

1つ目は「場所をまたいで広げない」。本物の散乱は、鼻に当たった光が頬から出てくる——ある点の色が、まわりの点に当たった光で決まる。それを描くには、照らした結果を画面か UV の上でぼかす別のパスが要る。今日の作り方は、画素が自分の N・L だけを見て「境目の近くなら赤みを足す」。にじむ「ように見える」だけだが、MToon の1パスの中で済む(要点1)。

2つ目は「境目からの距離 d を作る」。MToon の影の度合いは linearstep(-1 + toony, 1 - toony, N・L + shift) なので、ちょうど半分になるのは N・L = -shift。そこを 0、受光の中心を 1、影の奥を -1 にそろえた d に、表層と深層の2本の帯を乗せる(要点2・3)。

glsl
// mtoon.frag(Day 74)。直接光の2色はそのままにして、上から足す
float d = BoundaryDistance(nDotL, shift);                       // -1 影の奥 / 0 境目 / 1 受光の中心
vec3 ramp = SssRamp(d);                                         // 境目の近くだけ色味(両端は白)
sss += (SssBoundary(d, ramp) + SssTransmission(nDotL, l, v, ramp)) * 光の色 * マスク * 強さ;
color = direct + indirect + rim + emissive + sss;

3つ目は「このアバターでは、そのままでは見えない」。AvatarSample_A の顔は影の色がベースカラーと同じで、体と服は shift 1(影の側が無い)。記事の作り方は2段影のある絵が前提なので、境目に帯を足しても、境目そのものが絵に出ていない。F10 の試しで顔に2段影を付けると、記事の比較画像と同じ見え方になる(試して分かったこと)。上の実験台で「顔(ファイルの値)」と「顔に2段影」を切り替えると、同じ散乱でも見え方が変わる。

理論の要点

1. 表面下散乱の4つの作り方 — 場所をまたいで広げるか

肌に入った光は、中で何度も向きを変え、入った点から数ミリ離れた所から出てくる。赤い光ほど遠くまで届く(血と皮下組織が青と緑を先に吸う)ので、影の境目の影の側が赤くにじむ。リアルタイムの作り方は、「どこで広げるか」で4つに分かれる(記事の比較)。

作り方どこで広げるか必要なものトゥーンとの相性
スクリーンスペース照らした結果を画面の上でぼかす専用のパス・中間バッファ・深度(奥行きで広げる幅を変える)2段影の段差までぼける
テクスチャスペース照らした結果を UV の上でぼかすUV の重なりが無いこと・照らした絵を描くパスいちばん肌らしいが重い
Pre-Integrated広げない。N・L で引く表に、広げた結果を焼いておく表(1枚のテクスチャ)2段影を保てる
透けの近似広げない。逆光の向きと厚みで透けを足す厚み(マスク)境目のにじみは作れない

記事が選び、今日移すのは下の2つの組み合わせ。どちらも「広げない」ので1パスで済む。代わりに失うものがある。

  • 場所をまたぐ拡散は作れない。鼻に当たった光が頬へ回る、指の間から光が漏れる、のような絵は、まわりの画素を見ないと描けない
  • 落ち影の縁にはにじまない(記事)。境目は N・L から作るので、髪が顔に落とす影の縁は境目にならない(今日は F5 で縁も境目にできるが、幅は PCF のぼけの中だけ。要点2)
  • 記事も断っているとおり、Pre-Integrated の忠実な実装ではない。本来の表は「N・L と曲率」の2次元で、拡散の形を積分して焼く。記事と今日は、曲率を見ずに、帯の形を式で決める

2. 影の境目からの距離 d — MToon の境目は N・L = -shift

MToon の影の度合い(Day 68 の要点2)は shading = linearstep(-1 + toony, 1 - toony, N・L + shift)。ちょうど半分(明るい側と影の色の真ん中)になるのは N・L + shift = 0、つまり境目 b = -shift。そこからの距離を、両側で別々に割って -1〜1 にそろえる。

text
b = -shift
d = N・L >= b ? (N・L - b) / (1 - b)      // 明るい側: 境目で 0、N・L = 1 で 1
              : (N・L - b) / (1 + b)      // 影の側:   境目で 0、N・L = -1 で -1

片側だけで割ると、境目が真ん中に無いマテリアル(髪は b = 0.35)で、明るい側と影の側の帯の幅が違って見える。両側を別々に割ると、どのマテリアルでも「境目から端まで」が同じ 1 になり、帯の幅のつまみを共有できる。

マテリアル(AvatarSample_A)shift / toony境目 bd
顔(Face_00_SKIN)-0.05 / 0.05N・L = 0.05N・L 0.525 で 0.5、-1 で -1
髪(HAIR_01〜04)-0.35 / 0.35N・L = 0.35N・L -0.325 で -0.5
体と服(Body_00_SKIN・CLOTH)1 / 1N・L = -1(影の側が無い)いつも 1

影の側が無いマテリアルは、いつも受光の中心(d = 1)にいる扱いにする。1 + b = 0 で割れないからではなく、見えている境目が無いところに、にじませる相手は無いから。そのまま式に通すと、真後ろ(N・L が -1 に近い所)だけに帯が乗り、境目の無い体の背中に赤い縁取りが出る。

F5(落ち影の境目)を入れると、PCF の割合 0〜1 を shadow x 2 - 1 で -1〜1 に引き直し、min(d, それ) を取る。体と服にとっては、これが唯一の境目になる。ただし PCF のぼけは数テクセルしかないので、帯はいつも細い。

3. 境目の2本の帯と、散乱色のランプ

境目の近くに、幅の違う2本の帯を置く。表層は狭く明るい色(浅く散ってすぐ出てきた光)、深層は広く暗い赤(奥まで潜って血の色を拾った光)。

text
表層 = saturate(1 - |d| / 表層の半幅)²            半幅 0.25
深層 = saturate(1 - |d| / max(深層の半幅, 表層の半幅))²   半幅 0.6
重み = lerp(0.45, 1, saturate(-d / 深層の半幅))      // 明るい側は 0.45、影の奥ほど 1
境目の帯 = (表層の色 x ランプ x 表層 + 深層の色 x ランプ x 深層 x 0.6) x 重み
  • 2乗するのは、1次のままだと帯の端で傾きが急に 0 になり、帯の形が線として見えるから(下の実験台で「1次」に切り替えると、帯の端に角が出る)
  • 明るい側を 0.45 倍にするのは、明るい側は直接光でもともと明るく、足した色が埋もれて白っぽく濁るだけだから。実機ではもっとはっきりしていて、明るい側の肌は R が 1 を超えてすでに 1 で切れている(Day 72 のキャラの出口)。赤を足しても画面の値は変わらない(要点6)
  • ランプ(256x4)は帯に色味を付けるだけ。横が d(u = d x 0.5 + 0.5)、両端は白(色を変えない)、真ん中付近だけ色味が乗る。縦は下の2行が夜(寒色)、上の2行が昼(暖色)。床の上は昼、裏通りは夜の段を引く

記事のランプは画家が描いたテクスチャ。今日は画像をリポジトリに足さず、ToonSss.CreateRamp が式で作る(中央から u で 0.35 離れたら白、その間は smoothstep)。sRGB にしない・ミップを付けない・端で止めるの3つが要る(ToonSss.Load のコメント)。

4. 逆光の透け — 厚みの代わりにマスク

text
透け = saturate(-L・V)⁴ x saturate(-N・L x 0.5 + 0.5) x 深層の色 x ランプ x 0.8
  • 前半は「光がカメラの向こうから来ているか」。L は光へ向かう向き、V はカメラへ向かう向きなので、光源を見つめるときに -L・V = 1。4乗で、真向かいの狭い範囲に絞る(-L・V = 0.5 なら 0.0625)
  • 後半は「その面が光に背を向けているか」。光の当たる側の面は透けではなく直接光で明るいので、背を向けた面ほど強くする(境目の面で半分)
  • 厚みは見ていない。本来は薄い所(耳・指・鼻)ほど透けるので、Barré-Brisebois の作り方は厚みのテクスチャを焼く。記事も今日も、マスクが厚みを兼ねる(要点5)

体と服は shift 1 なので、逆光でも MToon の色は明るい側のまま(影が出ない設定)。体の散乱は透けだけになる。実験台で「体」を選び、光の向きを 180 にすると、境目の帯は出ずに、縁の内側(光に背を向けた面)だけが赤くなる。

5. マスク — 肌のマテリアル x 肌らしさ

記事のマスクは、ベースカラーと同じ UV の R に「透けの強さ」を描いたテクスチャ。AvatarSample_A には無いので、2段で代用する。

  1. マテリアル1枚ごとに 1 か 0。VRoid はマテリアル名の末尾に部位を付ける(_SKIN / _HAIR / _CLOTH / _EYE / _FACE)。_SKIN の2枚(顔と体)だけが 1
  2. 画素ごとの肌らしさを掛ける。体のテクスチャにはタイツとインナーも描かれているので、1 だけでは逆光で脚とインナーが赤茶に透ける。ベースカラー(リニア)が明るく、暖かい色だけを残す
glsl
float SkinLikeness(vec3 c)   // c はリニアのベースカラー
{
    float luminance = dot(c, vec3(0.2126, 0.7152, 0.0722));
    return smoothstep(0.2, 0.45, luminance) * smoothstep(0.03, 0.12, c.r - c.b);
}

しきい値は、顔と体のテクスチャの画素を数えて決めた。肌は輝度 0.6〜0.9・R - B が 0.2〜0.5。タイツと黒いインナーは輝度 0.1 以下。白い布は R - B がほぼ 0。この式は画家のマスクの代役で、このアバターでしか通用しない(肌色に近い服を着たアバターでは服も透ける。歪みの1つ目)。

6. どこに足すか — 2色の上に、光ごとに

Pre-Integrated の元の作り方は、ランバートの N・L の代わりに表を引く——拡散の明るさそのものを置き換える。トゥーンでそれをすると、作者が塗った影の色と境目の形が変わってしまう。記事と同じく、MToon の直接光(影の色とベースカラーの2色)はそのままにして、上から足す。

  • 光ごとに足す。太陽の分を足したあと、点光源のループの中でも同じ式で足す。記事はメインライトだけだが、夜の裏通りでは月が暗く、灯りのほうが肌を照らす(試して分かったこと: 点光源を外すと散乱がほぼ消える)。点光源は影を落とさないので、F5 は太陽にだけ効く
  • 光の色を掛ける。夜の灯りの橙で照らせば、散乱もその色になる。ランプの夜の段(寒色)は、月と灯りの色に寄りすぎないように赤みを抑える役
  • 出口は Day 72 のキャラの出口(1 で切って sRGB)。足した結果が 1 を超えたチャンネルは切れる。明るい側に赤を足しても見えないのはこのため。散乱が絵に出るのは、1 より十分暗い所だけ——記事の 0.45 は、ここで理屈が通る。影の色が明るすぎると、影の側でも R が切れる。そのときは足した赤が消えて G と B だけが増え、境目の影が赤くならずに白っぽくなる(試して分かったこと)

MToon とは別のクラスにした理由

MToon は「ファイルに書かれた値だけを持つ。こちらの判断で足した値は1つも無い」と決めたクラス(Day 68)。表面下散乱のつまみは全部こちらの判断(記事のプロパティの名前と意味を借り、値はこのアバターと照明に合わせて決めた)。同じクラスに混ぜると、どこまでが作者の指定で、どこからが自分の味付けかが読めなくなる。

置き場所の案良いところ困るところ
A. MToon にプロパティを足すマテリアルごとに値を持てる「ファイルの値だけ」の約束が崩れる。VRM を書き出す道具が無い値を、マテリアルごとに持っても埋める人がいない
B. 今日: ToonSss を1つ、Program が持つMToon は Day 73b のまま。OFF にすれば仕様どおりの絵だと、コードの形で言えるマテリアルごとの値は持てない(マスクの 1 か 0 だけ。改造課題1)
C. 別のシェーダ(MToon の写し + 散乱)MToon のシェーダに手を入れない402 行の写しが2本になり、MToon を直すたびに両方を直す

シェーダだけは C と逆に、mtoon.frag に足した。散乱は「光ごとの N・L」「境目の shift」「落ち影の割合」を MToon の計算の途中から借りるので、別のパスにすると全部をもう一度計算することになる。代わりに uSssEnabled が 0 なら何もしない(OFF のとき Day 73b と1画素も違わないことを確かめた)。

今日残した歪み

1つ目: マスクは式の代役。肌らしさのしきい値は AvatarSample_A のテクスチャに合わせて決めた。肌色に近い服(ベージュのニット)や、暗い肌のアバターでは外れる。本来はアバターごとに画家がマスクを描く。直すなら改造課題2(焼いたマスクに筆を入れられるようにする)。

2つ目: 透けは影を見ない。壁の陰に立っていても、壁の向こうの太陽に向かえば透ける。点光源は影を落とさないので、灯りとのあいだに何があっても透ける。夜の裏通りでは灯りとキャラのあいだに物が少ないので目立たない。

3つ目: 「顔に2段影」の試しは、表情の覚えた色を書き換える。Day 69 の「赤面」が顔の影の色に色の割り当てを持っていて、毎フレーム「読んだときの色」へ戻す。マテリアルだけ書き換えると次のフレームで元に戻るので、ColorBind.Initial を書けるようにした(Model に1行)。試しのために Model へ手を入れた形で、ファイルの値を実行中に変える仕組み(エディタ)を作るときに、まとめて考え直す。

4つ目: アウトラインの回でも散乱を計算して捨てる。線の色で上書きするので結果には出ない。線を持つ顔と体の分だけ、無駄な計算をしている(uOutlinePass で枝を切れば済むが、今日は式を読みやすいほうにした。時間は測っていない)。

5つ目: ランプは式から作る。画家が描き直す前の「たたき台」で、色味を変えるには C# を書き換えてビルドし直す。記事のように PNG を読むなら、LoadTexture(path, generateMipmaps: false, srgb: false) と端で止める設定の3つを守る。

6つ目: 落ち影の境目は PCF の幅しかない。F5 の帯の幅は、影の縁のぼけ(3x3 なら 1 テクセルほど)で決まり、つまみの半幅とは関係が無い。広げるには影の縁そのものをぼかす(PCSS など)必要がある。

改造課題

課題1(易): 部位ごとの透けの強さ

ToonSss.MaskOf を、マテリアルごとに 0〜1 の値を返す形にする(顔 1.0、体 0.6 など)。体は厚い(胴や脚)ので顔より透けにくい、という差を付ける。F8 の逆光で首と手の透け方が顔とどう変わるかを見る。さらに、顔の中でも耳だけ強くするには何が要るか(画素ごとの情報が要る)を考える——課題2への入口。

課題2(中): 肌らしさをテクスチャに焼く

シェーダが毎画素計算している SkinLikeness を、起動時に CPU で体と顔のベースカラーの絵から計算し、R8 のテクスチャ(Texture.CreateR8)に焼く。シェーダは焼いたマスクを読むだけにする(記事と同じ形)。焼いた結果を PNG に書き出し(Screenshot の PNG の書き方が使える)、画像編集ソフトで耳を明るく塗ってから読み直せるようにすると、「画家が描くマスク」の流れが一通りそろう。

課題3(難): 場所をまたぐ拡散を、キャラの画素だけで

要点1の表のいちばん上(スクリーンスペース)を、Day 72 の「キャラの割合」(シーンのバッファのアルファ)を使って作る。キャラを描いたあとに、割合が 1 の画素だけを横・縦の2回に分けてぼかし(Jimenez の分離ぼかし。幅は深度で割って、遠いほど狭く)、ぼかした色と元の色の差を、肌らしさの分だけ戻す。今日の帯と並べて、鼻の影が頬へにじむか、2段影の段差がぼけるか(記事の言う短所)を確かめる。
