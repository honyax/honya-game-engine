今日いちばん大事な3つ

1つ目は「形と色を分ける」。G-Buffer に書くのは光を当てるための材料だが、そのうち法線と距離は、SSAO のような画面の処理も読む。キャラの色の材料(影の色・境目)は G-Buffer に書けないが、形なら書ける。形だけを書いて画面の処理と分け合い、色は Day 68 のフォワードパスで付ける(要点1)。

2つ目は「ステンシルで、ライティングパスに触らせない」。キャラを G-Buffer に書くと、ライティングパスはその画素を PBR の物として照らそうとする。深度の隣の 8bit に「キャラ」の印 1 を書き、ライティングパスは NotEqual 1 の画素だけを塗る。ステンシルの試験は画素シェーダの前にあるので、外した画素では deferred.frag が走りもしない(要点2)。

C#
// G-Buffer パス: キャラを描く間だけ、深度に勝った画素へ 1 を書く(GBuffer.BeginCharacter)
_gl.StencilFunc(StencilFunction.Always, CharacterStencil, 0xFF);
_gl.StencilOp(StencilOp.Keep, StencilOp.Keep, StencilOp.Replace);

// ライティングパス: 印が 1 ではない画素だけ照らす。印は読むだけ(DeferredLighting.Render)
_gl.StencilMask(0x00);
_gl.StencilFunc(StencilFunction.Notequal, GBuffer.CharacterStencil, 0xFF);

3つ目は「G-Buffer の深度が、そのまま Z プレパスになる」。キャラの深度は G-Buffer パスで決まっているので、色のパスは深度を Equal で比べるだけでよい。いちばん手前の面の画素だけが通り、MToon の画素シェーダは1画素につき1回しか走らない(裏通りの全身で 113,664 回 → 64,219 回)。そのためには、G-Buffer の回と色の回で深度が最後の桁まで同じでなければならない——だから G-Buffer にも MToon の同じシェーダで書く(要点3・4)。

理論の要点

1. キャラとディファードの3つの混ぜ方

トゥーンのキャラを、ディファードで描くシーンに置く作り方は大きく3つある(手本の解析の冒頭の比べ方)。違いは「キャラが G-Buffer に何を書くか」と「キャラの色をどこで付けるか」。

作り方キャラが G-Buffer に書くものキャラの色を付ける所画面の処理(SSAO など)にキャラが居るか
キャラだけフォワード(解析の言う HoYoverse の並び。Day 68〜74)何も書かないシーンのライティングのあと、別のフォワードパス居ない(足元に暗がりが出ない)
形は共有、色はフォワード(Endfield。今日)深度・法線・速度などの形と、ステンシルの「キャラ」の印同じく別のフォワードパス。シーンのライティングは印の画素を飛ばす居る
両方ディファード(解析の言う鳴潮)形に加えて、トゥーンの色の材料も G-Buffer に書くG-Buffer から(解析は「同じライティングパスではなく、キャラの G-Buffer の段がすでにフォワードの照明に近い情報を書いている」とも書いている)居る

今日の作り方の値打ちは、キャラの色の描き方を1行も変えずに、画面の処理へキャラを入れられること。MToon の式は Day 68 のフォワードのまま、G-Buffer の欄も増やさない。代わりに、キャラの形を2回描く(G-Buffer の回と色の回)。3つ目の作り方は1回で済むが、G-Buffer にトゥーンの欄が要り、ライティングパスにトゥーンの枝が入る(改造課題3)。

2. ステンシル — 深度の隣の 8bit の印

ステンシルは、深度のバッファの隣に置く画素ごとの 8bit の整数。色にも深度にもならず、「この画素を描くかどうか」の試験にだけ使う。試験は2つの関数で決まる。

呼ぶもの決めることG-Buffer パス(キャラの間)ライティングパス
glStencilFunc(比べ方, 基準値, マスク)通すか。(基準値 & マスク) 比べ方 (いまの値 & マスク)Always, 1, 0xFF(いつも通す)Notequal, 1, 0xFF(印 1 ではない画素だけ)
glStencilOp(落ちた, 深度に落ちた, 通った)3つの場合のそれぞれで、何を書くかKeep, Keep, Replace(深度に勝った画素だけ 1 に)Keep, Keep, Keep
glStencilMask(ビット)書き込める桁0xFF0x00(読むだけ。光の球が重なっても印は変わらない)
  • 深度に負けた画素には印が付かない。glStencilOp の3つ目(両方通った)でだけ書くので、街灯の陰に入った腕には印が付かない(実験台の街灯の後ろ)。MASK の毛先も、discard で捨てた画素には書かれない
  • キャラはシーンの後ろで描く。キャラのあとに手前の物を描くと、その物が深度に勝って色と法線を上書きしても、印はキャラのまま残る(印を付けない物は、印を消しもしない)
  • 試験は画素シェーダの前。discard は画素シェーダを走らせてから捨てるが、ステンシルの試験に落ちた画素ではシェーダが走らない(GPU の早期の試験。深度の試験と同じ場所)
  • 毎フレーム 0 に消す。GBuffer.Begin と PostProcess.Begin で、色と深度と一緒に消す。消さないと、動いたキャラの抜け殻の形に、照らされない穴が残る。消すときは書き込みの口(glStencilMask)が開いていなければならないので、ライティングパスは最後に 0xFF へ戻して帰る

8bit あるのに今日使う値は 1 つだけ。手本の解析では、下位3ビットで「どの照明の式で照らすか」をシーンの 3 種類(0・1・2)とキャラ(4)に分け、上のビットに別の区別(キャラ 36・目 52)を持たせている。マスクを使えば、同じ 8bit に別々の意味を詰められる(改造課題1)。

3. 形は MToon の同じシェーダで書く

G-Buffer に書くのは Day 52 と同じ4枚。キャラは mtoon.frag に Day 52 の textured.frag と同じ枝を足して書く——表面が決まったところで打ち切る。

glsl
// mtoon.frag(Day 75a)。アルファで捨て、法線を決めたあと。光はまだ計算していない
if (uGBufferPass == 1)
{
    FragColor    = vec4(sqrt(max(base.rgb, vec3(0.0))), 1.0);   // 0: ベースカラー(表示用)
    GMaterial    = vec4(1.0, 1.0, 0.0, 1.0);                     // 1: AO 1 / 粗さ 1 / 金属 0
    GNormalDepth = vec4(normalize(mat3(uView) * n), -(uView * vec4(vWorldPos, 1.0)).z);  // 2: SSAO が読む
    GEmissive    = vec4(0.0, 0.0, 0.0, 1.0);
    return;
}
  • 画面の処理が読むのは2枚目だけ。ライティングパスは印の画素を飛ばすので、0・1・3 枚目は誰も読まない。それでも G-Buffer の表示(「ディファード」の F5)で意味の通る値を入れておく
  • 枝の場所は「捨てたあと、光の前」。MASK の毛先は捨ててから書くので、G-Buffer の形にも毛先の切り抜きが入る。両面のマテリアルの裏返し、法線マップも当てたあと——色の回と同じ法線になる
  • 同じシェーダにする本当の理由は頂点の側。色の回は深度を Equal で比べる(要点4)。G-Buffer を別のシェーダ(Day 37 の geometry.vert など)で書くと、スキニングの掛け算の順番が違うだけで深度の最後の桁がずれ、キャラに穴が開く。同じ mtoon.vert・同じ行列・同じ関節なら、同じ GPU で同じ値になる(自己チェック4: 穴 0)

出口に layout (location = N) を振るのも Day 52 と同じ。ふだんの色の回はシーンのバッファの1枚にしか繋がっていないので、1〜3 番は捨てられる。

4. Z プレパスと深度の Equal — 1画素1回

Day 74 までの色の回は、深度を Less で比べながら書いていた。パーツを描く順によっては、奥の面を塗ったあとで手前の面が塗り直す(重ね塗り)。MToon の画素シェーダは影・点光源 8 個・散乱・リムと重いので、塗り直しの分だけ無駄になる。

今日は G-Buffer パスがキャラの深度を先に書いている。ライティングパスの頭でシーンのバッファへ写してある(Day 52)ので、色の回の時点でいちばん手前の面の深度はもう決まっている。比べ方を Equal にし、深度は書かない。

色の回の比べ方通る画素裏通りの全身(1920x1080)で、不透明の回が塗った回数
形を入れない Less(Day 74)描いた時点で手前なら全部113,664 回(見えている画素の 1.77 倍)
形を入れて Equal(今日)G-Buffer の深度とぴったり同じ画素だけ64,219 回(印 64,213 画素の 1.00 倍。差は同じ深度で重なる数画素)
形を入れて Less(F7)無い。自分が書いた深度と「同じ」は「手前」ではない0 回(キャラが消え、線と半透明だけが残る)

これがエンジンで言う Z プレパス(深度プレパス)の効き目。手本はシーンもキャラも専用の深度プレパスで先に深度を書くが、このエンジンでは G-Buffer パスがその役を兼ねる。キャラの頂点の仕事(スキニング)は2回になるが、画素の仕事は1回に減る。実験台で「形を入れない」を選び、描く順を「奥から」にすると、重ね塗りがいちばん増える。

2回目の線(殻)と3回目の半透明(瞳・眉)は Day 68 のまま Less で描く。どちらも G-Buffer に書いていない(殻は表面ではなく、膜は後ろを隠さない)ので、比べる相手は不透明の面の深度になる。

5. 写し合う深度は、形式をそろえる

ライティングパスはシーンのバッファへ描くので、印もシーンのバッファの側に要る。G-Buffer の深度を写すときに、ステンシルも一緒に写す(BlitDepthTo(_post.Scene, stencil: true))。ここに glBlitFramebuffer の約束が効いてくる。

深度かステンシルを写すとき、写す元と先の深度とステンシルの形式がそろっていなければ GL_INVALID_OPERATION。

深度だけを写すときも同じで、ステンシルを持つ側と持たない側の間では写せない。シーンの深度は G-Buffer から来て、速度のバッファ(Day 54)と読む用のコピー(Day 50 のソフトパーティクル)へ出ていく。

深度を持つものDay 74Day 75a
色を持つフレームバッファの深度(G-Buffer・シーン・速度ほか)レンダーバッファ DepthComponent24(3B)レンダーバッファ Depth24Stencil8(4B)。DepthStencilAttachment に挿す
読む用のコピー(PostProcess.CaptureDepth)テクスチャ DepthComponent24テクスチャ Depth24Stencil8(CreateDepthOnly(..., stencil: true))。読むと深度が返るので、粒のシェーダは変わらない
シャドウマップテクスチャ DepthComponent24そのまま(誰とも写し合わない)

「どれとどれが写し合うか」を覚えておくより、色を持つフレームバッファの深度は全部同じ形式にしておくほうが間違えない。24bit の深度は GPU の中ではたいてい 32bit に置かれるので、8bit はその空きに入る。HUD と内訳のバイト数は 3B → 4B になり、Day 52 と Day 54 の自己チェックの「深度 3B」も 4B に直した。

6. 画面の処理は形しか見ない — SSAO と速度

SSAO(Day 37)が読むのは、ビュー空間の法線と距離だけ。キャラの法線と距離が G-Buffer の2枚目に入れば、SSAO はキャラを普通の物として扱う。足元の床と、キャラの後ろの壁に暗がりが出る。

  • フォワードのフレームでも入れる。Forward+ のときは G-Buffer が無く、SSAO は自分の幾何パスを描く。そこへキャラの不透明と MASK のパーツを足す(DrawVrmSsao)。Day 68 が「どちらでも入れない」にしたのは、片方だけだと描き方を切り替えたときに足元の暗がりが出たり消えたりするから。今日は「どちらでも入れる」にした
  • キャラ自身に AO を掛けるかは別の話。遮蔽率のテクスチャにはキャラの画素の値も入っている(腕の付け根・首まわり・髪の重なりが暗い)。掛けるかは見た目の判断で、MToon の陰影は直接光の2色で決めたいので既定は掛けない。F6 で環境光にだけ掛けられる(textured.frag の Day 37 と同じ約束)
  • 速度は今までどおり色の回が記録する。手本は G-Buffer の2枚目に動きを書くが、このエンジンの速度は別のパス(Day 54)で、物ごとに _motion.Record で覚えさせる。キャラは Day 68 から色の回で記録しているので、G-Buffer の回では記録しない(同じメッシュを2回記録すると、2回目を別の物として数える)

G-Buffer に書くシェーダの選び方

キャラの形を G-Buffer に書くシェーダには、ほかに2つの案があった。決め手は要点3の「深度が最後の桁まで同じか」。

案良いところ困るところ
A. SSAO の幾何シェーダ(geometry.vert / .frag。Ssao.Draw で描く)形だけを書く専用の軽いシェーダ。フォワードの SSAO と同じ道具頂点シェーダが違う(uModelView と uProjection に分けて掛ける)ので、色の回の Equal で穴が開く。アルファを見ないので毛先が四角い。出口が1つで、G-Buffer の4枚に書けない
B. textured.frag の G-Buffer の枝(Day 52)シーンと同じ枝をそのまま使える頂点シェーダが textured.vert になる。両面の裏返しも無い。MToon のマテリアルの値の送り方(MToon.Apply)と別に、PBR の値を送る道が要る
C. 今日: mtoon.frag に G-Buffer の枝色の回と同じ頂点シェーダ・同じ捨て方・同じ法線。DrawMToonPart をそのまま呼べるG-Buffer の回でも MToon の値を全部送る(使わない値も。歪みの4つ目)。MToon のシェーダが G-Buffer の並び(GBuffer.Layout)を知る

フォワードのフレームだけは A を使う(DrawVrmSsao)。そこでは色の回が Less で深度を書くので、深度が食い違っても穴は開かない。毛先が四角いままなのが、ディファードとの小さな違いとして残る(歪みの1つ目)。

だれが何を知っているか

コメントを落としてから型名を拾って確かめた(DeferredLighting.cs が使う型は Camera / GBuffer / PointLight / Shader / RenderResources / Mesh / Primitives などで、MToon も VrmAvatar も出てこない。Framebuffer.cs は Texture だけ)。

Render/GBuffer印の値 CharacterStencil、付け方(勝った画素だけ)、毎フレーム消すこと何に印を付けるか(キャラか、MToon か)

印の値は GBuffer に置いた。付ける側(GBuffer.BeginCharacter)と読む側(DeferredLighting)が同じ定数を見るので、値を変えても1か所で済む。

今日残した歪み

1つ目: フォワードの SSAO の幾何パスはアルファを見ない。DrawVrmSsao は geometry.frag で描くので、MASK の毛先が四角いまま遮蔽物になる。ディファード(mtoon.frag の枝で捨ててから書く)と、形が毛先の分だけ違う。直すなら改造課題2。

2つ目: 線(アウトライン)と半透明は G-Buffer に居ない。線の画素は印の外なので、ライティングパスはその下の壁や床を照らし、そのあと線の色で上書きされる(線の幅のぶん、捨てる計算をしている)。SSAO にも線の幅は入らない。数画素の幅なので、絵には出ていない。

3つ目: ステンシルの 8bit のうち、使っているのは 1 の値1つだけ。手本は下位3ビットで照明の式を選び、上のビットで目を分けている。このエンジンのライティングパスは1本なので、今は分ける相手がいない。

4つ目: G-Buffer の回でも ApplyMToonFrame を呼ぶ。形しか書かないのに、影・IBL・プローブ・散乱のランプまで送っている(灯りだけは 0 個にした)。送るのは CPU の仕事で、フレームに1回なので測っていない。G-Buffer の回だけ行列と関節とアルファの値に絞るなら、ApplyMToonFrame を2つに割ることになる。

5つ目: 自己チェックの小さな描画が、深度テストを自分で入れている。OnRender では、深度テストを入れるのは空の描画(DrawSkybox)で、ディファードのライティングパスは借りた状態を返すだけ。空を描かない自己チェックでは深度テストが切れたままで、色の回が Equal も Less も比べずに塗った(試して分かったこと)。「だれが深度テストを入れるか」がどこにも書かれていない形は Day 74 以前からあり、今日表に出た。

6つ目: キャラの頂点の仕事が2回になった。スキニング(関節 60 本)と法線の計算を、G-Buffer の回と色の回で2回する。画素の仕事は 1.77 倍から 1 倍に減ったが、時間は測っていない(F11 の内訳は回数だけ)。

試して分かったこと

  • 形を入れなければ Day 74 と1画素も違わない。裏通りを同じ台本で撮り、ディファードでも Forward+ でも全画素で差 0。深度の形式をステンシル付きにしたことは、絵に1画素も出ていない
  • 入れると、差はキャラのまわりの床と壁に出る。裏通りのディファードで 77,175 画素が変わり、最大の差は 255 段階の 14。キャラの内側で変わったのは縁の数百画素だけ(キャラの色の描き方は変わっていない)
  • 夜の裏通りでは、合成した絵の差は小さい。遮蔽率の表示(F5)では足元と脚のまわりの床がはっきり暗いが、SSAO が掛かるのは環境光(夜の空とプローブ)だけなので、絵の上では数段階。足元に寄った絵で、8 段階以上暗くなったのは 235 画素だった。形が入ったかどうかは、遮蔽率の表示で見るのが確か
  • 遮蔽率の表示で、脚のまわりの床に放射状の薄い筋が出る。細い脚の両側で、SSAO の標本が脚に当たる向きと当たらない向きに分かれるように見える(半径 1m・標本 32 本・ぼかし ON の既定のまま)。原因は確かめていない
  • 色を消すと穴、外さないと灰色のキャラ。F4 だけだと、キャラの形に夜空が抜ける(ライティングパスが飛ばした画素)。F3 で外さないようにすると、G-Buffer の枝が書いたベースカラーと粗さ 1 で、灰色がかった PBR のキャラが出る
  • 最初の自己チェックで、Equal も Less も形を入れないのも、同じ 175,966 回だった。小さな描画で空を描かなかったので、深度テストが切れたままだった(歪みの5つ目)。入れると Equal 64,219 回 / Less 0 回 / 形なし 113,664 回に分かれた
  • Equal でも、印より数画素多く塗る。64,213 画素に 64,219 回(別の走りでは 64,157 に 64,165)。2つの面がちょうど同じ深度で重なる画素があり、どちらも通る。どの面どうしかは突き止めていない。穴(印の画素なのに塗れない)は 0

キャラが出ていなければ、裏通りに立たせてから測る。影 → G-Buffer → SSAO → ライティング → キャラの色を OnRender と同じ順に呼んで1フレームを描き、ステンシル・シーンの色とアルファ・G-Buffer の距離・遮蔽率を読み返す。それを切り替えを変えて5回(今日の形 / 形なし / Less / 色なしで外す / 色なしで外さない)繰り返す。不透明の回が塗った回数は GL_SAMPLES_PASSED の問い合わせで数える。数は揺れもので数十画素ずつ揺れる(別の走りでは印 64,157・Equal 64,165)。切り替えは全部元に戻す。

改造課題

課題1(易): 印を2種類にする

髪のパーツ(マテリアル名に _HAIR)には印 2、ほかのキャラのパーツには印 1 を書く。ライティングパスは「印が 0 の画素だけ照らす」(StencilFunc(Equal, 0, 0xFF))に変え、印の表示は 1 と 2 を別の色にする。NotEqual 1 のままだと何が起きるか(髪だけ PBR で照らされ、MToon が上書きする)を先に予想してから確かめる。手本の「下位3ビットで分類、上のビットで目」に近づけるなら、マスク(glStencilFunc の3つ目の引数)をどう使うかも考える。

課題2(中): フォワードの SSAO でも毛先を捨てる

歪みの1つ目。geometry.vert に UV を通し、geometry.frag にベースカラーのテクスチャとしきい値を足して、MASK のパーツだけ discard する(Day 68 の改造課題3「影パスでアルファを見る」と同じ形)。Ssao.Draw の既存の呼び出しを1つも書き換えずに済む形(既定引数)にできるか。ディファードと Forward+ で、遮蔽率の表示の毛先の形を見比べる。

課題3(難): キャラだけを照らす2本目のライティングパス

要点1の表の3つ目(両方ディファード)を試す。G-Buffer の空き(1枚目の A・2枚目は埋まっている・4枚目の A)に、MToon の shift と toony と影の色の明るさを詰め、ライティングパスに印 1 の画素だけを塗る2本目(StencilFunc(Equal, 1, 0xFF))を足して、太陽の2色だけを出す。今日のフォワードの絵と並べ、何が足りないか(影の色のテクスチャ・リム・マットキャップ・点光源の上限・半透明)を数える。G-Buffer に欄を足す代償(1画素のバイト数)も GBuffer.ByteSize で出す。
