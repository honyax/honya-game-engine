今日いちばん大事な3つ

1つ目は「箱を小さくすれば、テクセルは細かくなる」。シャドウマップの1テクセルの大きさは「箱の幅 / 解像度」で決まる。解像度を上げるより、写す範囲をキャラだけに絞るほうがずっと効く。同じ 2048 でも、半径 16m の世界の箱は 15.6mm、半径 1.2m のキャラの箱は 1.2mm(1/13)。深度のバイアスも範囲に比例するので、72mm から 1.8mm に縮む(要点1・2)。

// Program.RenderVrmCharacterShadow(Day 75b)。世界の影パスの直後に、Day 33 の道具の2つ目でキャラだけを焼く
(Vector3 center, float radius) = vrm.ShadowBounds(VrmPlacement(), VrmShadowMargin, VrmShadowRadiusStep);
_characterShadow.Radius = radius;                 // 関節を全部包む球(1.2m)
_characterShadow.Begin(_lightDirection, center);  // 光の向きは世界と同じ
DrawVrmShadow(_characterShadow);
_characterShadow.End(width, height);

2つ目は「答えを画面に1回だけ書いて、読む人がチャンネルを選ぶ」。シャドウマップを引く計算(位置を戻す・PCF)を、画面の画素ごとに1回だけ全画面のパスでやり、RG8 の1枚に書く。R は世界の影(Day 75a までのライティングパスと同じ答え)、G はキャラ専用の影 x R。シーンのライティングパスは R、MToon は G を読む。照らす人はもうシャドウマップを知らなくてよい(要点4・5)。

// deferred.frag(Day 75b)
float shadow = uScreenShadowEnabled == 1 ? texelFetch(uScreenShadow, pixel, 0).r : ShadowFactor(...);

// mtoon.frag の SunShadow(Day 75b)
vec2 rg = texelFetch(uScreenShadow, ivec2(gl_FragCoord.xy), 0).rg;
return uScreenShadowChannel == 1 ? rg.r : rg.g;

3つ目は「画面の影は、形が G-Buffer にあるから作れる」。画面の影の入力は G-Buffer の2枚目(法線と距離)だけ。Day 75a でキャラの形を入れたので、キャラの画素でも位置が戻せる。形を入れないと(Day 75a の F2)、キャラの画素には後ろの壁の距離が入っていて、壁の影の値になってしまう——そのとき MToon は画面の影を読まず、Day 74 までどおり自分でシャドウマップを引く(要点5)。

理論の要点

1. 1枚のシャドウマップでは、顔の影が拾えない

シャドウマップの細かさは「箱の幅 / 解像度」で決まる。完成版の裏通りは、太陽の仰角が 8 度しかなく、高さ 4m の建物が 28m 先まで影を落とすので、箱の半径を 16m にしてある(Day 39)。

世界のシャドウマップキャラ専用(今日)
箱の半径16m(シーンの設定)1.2m(関節を全部包む球。余白 15cm)
解像度20482048
1テクセル15.6mm1.2mm(1/13)
深度のバイアス(DepthBias x 深度の範囲)0.0015 x 48m = 72mm(傾きで最大 6 倍足される)0.0005 x 3.6m = 1.8mm
顔の幅(約 15cm)に入るテクセル約 10約 130
VRAM12.0MB12.0MB(深度 3B / 画素)

バイアスが問題の本体だ。比べる深度を「バイアスだけ手前」にずらすので、遮る物と受ける面の隙間がバイアスより狭いと、影にならない。前髪と額の隙間は 2〜3cm、世界のバイアスは 7cm。だから世界の影では、前髪の影が顔に落ちない。バイアスを小さくすればよさそうだが、テクセルが 1.6cm もあると、曲がった面では1テクセルの中で深度が数 cm 変わり、自分自身を影にする(シャドウアクネ)。細かい影には、細かいテクセルと小さいバイアスの両方が要る。上の実験台で「世界(R)」を選ぶと、前髪の影が消える。

裏通りの夕暮れで数えると、キャラの画素 64,213 のうち、世界の影(R)で影になるのは 3,256(5.1%)、キャラ専用の影を掛けた G では 9,855(15.3%)。G でだけ影になる画素が 6,599——前髪の影・顎の下・髪どうしの影だ。

2. キャラ専用のシャドウマップ — 箱をキャラに合わせる

キャラだけを、キャラを包む小さな箱で焼く。道具は Day 33 の ShadowMap のままで、2つ目を作り、毎フレーム中心と半径をキャラに合わせる。光の向きは世界と同じ。

  • 測るのはスキンの関節の全部(VrmAvatar.ShadowBounds)。ヒューマノイドの骨だけだと、髪とスカートの揺れる骨(VRoid の J_Sec_*)が入らず、毛先の影が箱からはみ出して切れる。AvatarSample_A は関節 81 本、T ポーズでいちばん遠い関節は中心から 0.84m
  • 余白 15cm。関節は皮膚の内側にあるので、毛先・指先・靴の分を足す
  • 半径は 10cm 刻みに切り上げる。待機のアニメーションでも関節の箱は毎フレーム数 mm 伸び縮みする。半径がそのまま1テクセルの大きさになるので、刻まないと影の縁が息をするたびに揺れる
  • 箱は球(正射影の幅は直径)。キャラが向きを変えても大きさが変わらない。光の向きに合わせて締めた直方体にすれば、T ポーズの腕の分だけ細かくできる
  • 焼くのはキャラだけ。この箱が答えるのは「キャラ自身が落とす影」だけで、建物の影は世界のシャドウマップが答える(要点4の G = キャラ x R)

バイアスは世界の 1/3(0.0005)にした。バイアスは「深度の範囲に対する割合」なので、範囲が 48m から 3.6m に縮んだ時点で、同じ 0.0015 でも 4.5mm になる。それでも鼻や前髪の影には大きく、影が物から浮く。逆に解像度を 512 に下げると、1テクセル 4.7mm に対してバイアス 1.8mm は足りず、顔と首にアクネの縞が出る(完成条件3。実験台で 512 を選ぶ)。バイアスはテクセルの大きさに比例させるのが筋で、今日は固定のまま残した(課題1)。

3. 箱の奥より遠い受け手 — 1.0 で止める

キャラの影は、床にも後ろの壁にも落ちる。後ろの壁は、キャラの箱の奥(中心から半径の 1.5 倍)よりずっと遠い。そこで光の空間で見ると話が簡単になる——光は平行なので、キャラの影はどこに落ちても、光の空間ではキャラの真後ろにある。箱の横の範囲(xy)はキャラの影を全部覆っていて、はみ出すのは奥行き(z)だけだ。

z が 1 を超えた受け手の扱いキャラの真後ろの壁箱の横の外の壁(境界色 1.0 が返る)
そのまま比べる影(正しい)影(z − バイアス > 1.0 なので。箱の外が全部暗くなる)
当たっている扱い(Day 33 の世界の影のやり方)当たる(キャラの影が消える)当たる
1.0 で止める(今日)影(1.0 − バイアス > キャラの深度)当たる(1.0 − バイアス > 1.0 は成り立たない)
glsl
// screen-shadow.frag(Day 75b)
characterProj.z = min(characterProj.z, 1.0);   // 箱の奥より遠い受け手は、箱の奥の面に置く

世界のシャドウマップが「z > 1 は当たっている」にしてよかったのは、箱がシーン全体を覆っていて、奥の外に受け手がほとんど無いから。キャラの箱は小さいので、奥の外こそ影の落ちる先になる。下の実験台で3つの扱いを切り替えられる。

4. 画面の影 — 1枚に2つの答え

Day 74 までは、照らす人(textured.frag・deferred.frag・mtoon.frag)がそれぞれシャドウマップを引いていた。シャドウマップが2枚になり、読む人によって欲しい答えが違う。そこで引く仕事を全画面の1パスにまとめ、答えを画面の画素ごとに書いておく。これが画面の影(ScreenShadow)。

  • R = 世界の影。deferred.frag の ShadowFactor と同じ式・同じバイアス・同じ PCF。位置の戻し方も同じにした(uv = gl_FragCoord.xy / uScreenSize。fullscreen.vert の vUv を使うと、補間の丸めで PCF の 25 タップのうち1つが境目で入れ替わる画素が出た)
  • G = キャラ専用の影 x R。キャラ専用のシャドウマップにはキャラしか居ないので、建物や街灯の影の中に立ったときのために R を掛ける。キャラの影が届かない所では G = R(自己チェック5)
  • RG8(1画素 2B、4.0MB)。影の値は PCF のタップの平均(5x5 なら 1/25 刻み)で、もともと粗い。8bit に丸めた差は 1/510 以下
  • 空は当たっている扱い(距離 0 の画素は R = G = 1)

手本との違いもある。手本の画面の影は、半分・4分の1の解像度で遮蔽(カプセルによる近似)を計算してから原寸で合わせ、別のパスの接触影(画面空間のレイ)も持っている。このエンジンは原寸で2枚を引くだけにした。

5. 読む側で使い分ける

読む人画面の影があるフレーム無いフレーム(Forward+・F2 で切った)
ライティングパス(deferred.frag)R(Day 75a と同じ答え。違いは 8bit の丸めだけ)自分で世界のシャドウマップを引く
MToon の不透明と半透明の回G(キャラの形が G-Buffer にあるときだけ。F3 で R も選べる)自分で世界のシャドウマップを引く(Day 74 まで)
MToon の線の回いつも自分で引く。線は表面の外へ押し出した殻なので、その画素の画面の影はキャラの後ろの壁や床のもの——縁に壁の影の色の線が出てしまう
textured.frag(フォワードのシーン)読み口を作っていない(画面の影はディファードのフレームでしか作らないので)

瞳と眉(半透明)は G-Buffer に居ないが、その画素の G-Buffer には下の顔が入っているので、顔の G を読む。手本は目のまわりと瞳に R を読ませている。

読むかどうかは「その画面の影が今のものか」で決める(設計書「世代の番号」)。フォワードのフレームでは作らないので、古い影を読まないように C# が uScreenShadowEnabled / uScreenShadowChannel を 0 にして送る。

6. このアバターは影の色 = ベースカラー

作ってみて分かったことがある。AvatarSample_A は、口以外の全部のマテリアルで、影の色の絵(shadeMultiplyTexture)がベースカラーの絵と同じで、影の色の係数も白(Day 74 の「顔に2段影」の説明と同じ話)。MToon の陰影は「明るい側と影の側の2色から選ぶ」なので、2色が同じなら影に入っても色が変わらない。G が顔に前髪の影を正しく持っていても、合成した絵ではほぼ見えない(夕暮れの顔で、G と Day 75a の差は 56 画素)。

だから今日のページは、影の値そのものを見る表示(F4: 画面の影 R / G、MToon の影の度合い)を用意し、合成した絵で見比べたいときは F6(Day 74 の「顔に2段影」。顔の影の色を (0.60, 0.42, 0.46) 倍、toony 0.9)を使う。2段影にすると、顔のまわり 600x700 画素の切り出しで、G と R の絵は 8 段階以上違う画素が約 1.5 万になり、額に前髪の影がはっきり出る。

夕暮れの太陽も強く、顔は 255 で白飛びしている。影の色に変わっても、両方が白に張り付いて見分けられないことがある(2段影の影の色は暗いので見分けられる)。夜は月が 5% で、キャラの明るさはほとんど灯りが決めている(点光源は影を持たない)。

画面の影が古いかどうか — 世代の番号

最初は「フレームの頭で Ready を倒し、作ったら立てる」形にした。Day 52 の自己チェックが落ちた——「フォワードとディファードで同じ絵」が平均 11% 違った。Day 52 の自己チェックは自分で G-Buffer とシャドウマップを描き直し、DeferredLighting.Render を直接呼ぶ。画面の影はその前のフレームのまま「作った」ことになっていて、ライティングパスが別の絵の影を読んでいた。

画面の影は、G-Buffer と世界のシャドウマップの写しだ。写しが古いかどうかは、元が描き直されたかで決まる。そこで GBuffer と ShadowMap に「描き直した回数」(Generation。Begin のたびに 1 増える)を持たせ、ScreenShadow は作ったときの2つの番号を覚えておく。

C#
// ScreenShadow(Day 75b)
public bool Ready =>
    Enabled
    && _gbuffer is not null && _gbuffer.Generation == _gbufferGeneration
    && _world is not null && _world.Generation == _worldGeneration;

フォワードのフレームでは影パスがシャドウマップを焼き直すので番号が変わり、Ready は倒れる。だれかが G-Buffer を描き直しても倒れる。「いつ倒すか」をだれも覚えておかなくてよいのがこの形の値打ち。代わりに、GBuffer と ShadowMap が「写しを取る人がいる」ことに備えて番号を持つようになった(どちらも番号の使い道は知らない)。

今日残した歪み

  • 1つ目: 世界の影が、キャラ自身に落とす粗い影も G に入る。G = キャラ専用の影 x R で、R の世界のシャドウマップにはキャラも焼かれている。今の裏通りでは世界のバイアス(72mm)がキャラの凹凸より大きく、R の影はキャラ専用の影にすでに含まれる分しか出ない(「キャラの箱の手前より光に近い遮蔽物だけを数える」形と比べて、違ったのは 28 画素)。世界のバイアスを 0.0003 に下げると 1,156 画素が 0.25 以上暗くなる。シーンの設定によっては表に出る(課題3)
  • 2つ目: バイアスがテクセルの大きさに比例していない。解像度を 512 に下げると顔と首にアクネの縞が出る(課題1)
  • 3つ目: Forward+ のフレームでは、キャラ専用の影を使わない。画面の影は G-Buffer の距離から位置を戻すので、ディファードのフレームでしか作れない。Forward+ に切り替えると顔の前髪の影が消える。SSAO の幾何パスの距離を使えば作れる(Day 75a の DrawVrmSsao でキャラも入っている)
  • 4つ目: G を画面の全画素で作っている。G を読むのはキャラの画素(画面の 3.1%)と、その上の瞳・眉だけで、床と壁の G は誰も読まない(表示で街灯の影が抜けているのはそのため)。キャラ専用のシャドウマップの PCF の 9 タップを、残りの 97% でも引いている。時間は測っていない(課題2)
  • 5つ目: 箱の位置をテクセルに合わせていない。キャラが歩くと箱が少しずつ動き、テクセルの格子も一緒に動く。影の縁がちらつくはずだが、歩かせて確かめていない(世界のシャドウマップも同じで、Day 33 から合わせていない)
  • 6つ目: キャラ1人分だけ。手本は 1024 の枠を4つ持つアトラスで、複数のキャラ(か大事な物)に枠を割り振っている。このエンジンのキャラは1人なので、2048 の1枚にした

  • キャラ専用の影を切れば、Day 75a と1画素も違わない。夕暮れの裏通り・ディファード・全身を同じ台本で撮り、全画素で差 0
  • 使うと、シーンの画素は 8bit の丸めの分だけ変わる。キャラ以外の 200 万画素のうち、1% 以上違う成分は約 1,000 個で最大 2.0%。全部が半影の暗い端(PCF 25 タップの 1/25・2/25・3/25 が 8bit の段に乗らない所)

  • 世界の影(R)を MToon に読ませても、Day 75a とほとんど同じ。Day 75a の MToon は頂点から運んだ正確な位置で引き、R は G-Buffer の距離(16bit の浮動小数点)から戻した位置で引く。それでも絵の違いは縁の数千画素だけ(2段影で顔に寄った切り出しで、8 段階以上違うのは約 2,400 画素)
  • 合成した絵には、2段影にしないと出ない(要点6)。夕暮れの顔では、G と Day 75a の差が 56 画素だった。影の値の表示(F4)と MToon の影の度合いでは、G だけに前髪の影がはっきり出る
  • 「キャラの箱の手前より光に近い遮蔽物だけを世界の影として数える」形も作って比べた。受け手の深度を箱の光の側の端で止めて世界のシャドウマップと比べる、1行の min で書ける。今の裏通りでは差が 28 画素しか出ないので外した(歪みの1つ目・課題3)

改造課題

課題1(易): バイアスをテクセルの大きさに比例させる

歪みの2つ目。ShadowMap に「1テクセルあたりのバイアス」(例えば 1.5 テクセル)を持たせ、Apply と ScreenShadow.Render で送る uShadowBias を WorldPerTexel から計算する(深度の単位に直すには、範囲 3 x 半径で割る)。512 でアクネが消えること、4096 で前髪の影が浮かないことを、F4 の MToon の影の度合いで確かめる。世界の影に同じ式を当てると何 mm になるかも出す。

課題2(中): G をキャラの画素だけで作る

歪みの4つ目。画面の影のパスを2回に分け、1回目はステンシルの試験なしで R だけ(G には R をそのまま)、2回目は StencilFunc(Equal, 1, 0xFF) でキャラの印の画素だけ G を書き直す(Day 75a の印をそのまま使う。ColorMask で G だけ書く)。画面の影の書き込み先にはステンシルが無いので、G-Buffer の深度とステンシルを貸してもらう形を考える。瞳と眉(印の外)の G はどうなるかも見る。時間はタイマークエリで測る(ハーネスで全開の計測を回さないこと)。

課題3(難): 世界の影から、キャラ自身の粗い影を外す

歪みの1つ目。G の世界の影を「キャラの箱の光の側の端より光に近い遮蔽物だけ」にする。ShadowMap に世界の点を箱の深度(0〜1)に写す LightDepth を足し、箱の端(中心から光の来る方へ半径だけ戻った点)の世界での深度を送って、screen-shadow.frag で受け手の深度を min(proj.z, 端の深度) にしてから世界のシャドウマップと比べる。世界の DepthBias を 0.0003 に下げ、切る / 切らないで G を見比べる(試したときは 1,156 画素が 0.25 以上違った)。正射影なので端の深度が箱の横のどこでも同じになる理由と、キャラのすぐ前(1m 以内)にある物の影がキャラに落ちなくなる代償も説明する。
