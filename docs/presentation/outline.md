## 2. 各スライド

### 2-1. はじめに(3枚)

1. **タイトル**
2. **先に完成品**: Day 56 の最終デモ(夜の裏通りを三人称で走り回る。多光源・TAA・被写界深度)。「これを CPU で1ピクセル塗るところから作った」。規模の数字(約2.5か月で Day 01〜51、85 Day 分、C# 約6.7万行)
3. **自分に合った教材が欲しかった**
   - 既存の教材とのずれ: 言語(C++ 中心)、レイヤ(エンジンの使い方 or 低レイヤだけ)、順番、ペース
   - 自分の条件: **目的は学習(実用のエンジンは目指さない)**・C# メイン・ゲーム開発20年・1 Day ずつ自分のペース・「なるべく低いレイヤから」・最後に AAA 風のデモ
   - 条件を Claude Code に渡して、ロードマップ・計画書・答えのコードまで作らせた

### 2-2. 教材の作り方(5枚)

4. **ロードマップを対話で作る**
   - 右上の札から実際の `docs/roadmap.html` を別タブで開いて見せる
   - 方針の比較検討(ソフトウェアラスタライザ自作 / 生 OpenGL / Silk.NET / MonoGame)から相談し、結論と理由を残した
   - Phase 0〜8+教養編+VRM 編、Day 1〜73。各 Phase に「動くもの」のマイルストーン
   - 手持ちの教科書(ゲームグラフィックス特論、西川本)との対応表も作らせた
5. **1 Day の教材の形**
   - 計画書(HTML): ゴール / 理論の要点 / 図 / 実験台 / 差分 / 完成条件 / 改造課題
   - 答えのコード: 前 Day の完全コピー+その日の差分。どの Day でも単体で動く
   - 使い方は自由(写経・改造・読むだけ)。ここはさらっと
6. **実験台: 理論を動かして確かめる**
   - 計画書の中で、その日の理論をブラウザで動かせる部品
   - 右上の札から実際の `docs/plans/Day47.html` を別タブで開いて見せる(スライド内の枠は小さいので予告程度)
   - 例を見せる(物理のページで実演すると予告)
7. **Claude Code の仕掛け: create-day スキル**
   - `create-day` スキル: 「Day 47 を作成して」の一言で、計画書 → 答えのコード → 整形 → ビルド → 写経順の機械的な検算 → HTML の検証
   - 失敗したら手順をスキルに足す(写経順の漏れ → 検算手順を追加、など)
8. **教材を育てる**(自分に合わせて変え続けられるのが、自作教材のいちばんの利点)
   - 8/08 物理エンジンを途中で足した(最初の計画には無かった)
   - 8/15 卒業制作の題材を差し替え(数百体の敵 → スプライトバッチと ECS が「ゲームの必然」になる題材へ)
   - 9月 1 Day が膨らんだら a/b に分割(44a/44b、54a/54b など)
   - 10月 計画書を Markdown から HTML へ作り直し、図と実験台を足した
   - 10月 VRM 編(トゥーン調のアバター)を足した

### 2-3. 成果物(9枚)

全ページ共通の型:

```
+------------------------------------------------------------+
| テーマ名                                   [Day 43〜47]    |
+------------------------------+-----------------------------+
|                              |  毎フレームの流れ           |
|   動画 / 実験台              |  (1) → (2) → (3) ...        |
|                              |  (最後は次のフレームへ戻る) |
+------------------------------+-----------------------------+
| 一言: 作ってみて分かったこと                               |
+------------------------------------------------------------+
```

並びは Day 順。右上の帯でロードマップ上の位置を見せる。

| # | テーマ | Day | 毎フレームの流れ | 左に見せるもの | 一言 |
|---|---|---|---|---|---|
| 9 | 描画の土台 | 1〜13 | 頂点 → 行列で変換 → 透視除算 → 三角形を塗る → Z テスト → テクスチャ+陰影 → 画面へ転送 | ソフトラスタライザの回転モデル(Day 10) | GPU が裏でやっていることを、一度 CPU で全部書いた |
| 10 | レンダラとエンジンコア | 14〜24 | 入力 → 固定タイムステップで更新(ECS) → スプライトを溜めてソート → まとめて描く → 補間して表示 | 1万スプライト(Day 18) | 同じものを2回書く(GameObject → ECS)と、両設計の理由が腹に落ちる |
| 11 | 卒業制作 | 25〜30 | 入力 → 敵の湧き → 自動攻撃 → 格子で候補を絞る → 当たり判定 → レベルアップ | 見下ろし型アクション(Day 30) | エンジンで1本作ると、設計の穴が全部見える |
| 12 | HDR とポストエフェクト | 31, 37, 38 | シーンを HDR のバッファへ → SSAO → ブルーム → トーンマッピング → FXAA+色調整 | 機能の ON/OFF 比較 | 「映画っぽさ」の正体は後処理 |
| 13 | 材質と光 | 32〜36, 39〜40 | glTF 読み込み → 影の地図を描く → 法線マップ → PBR の反射 → 環境光(IBL) | デモ v1 のシーン(Day 40) | HDRI 1枚でシーンの説得力が激変する |
| 14 | キャラクター | 41〜42, 45b | 速度から歩き/走りの比率 → クリップをブレンド → ボーン行列 → スキニング / カプセルを坂・段差に沿って滑らせる | 歩き↔走りが繋がる動画(Day 42) | ブレンドの重みが移動速度そのもの |
| 15 | **ミニ物理エンジン** | 43〜47 | 力 → 速度を積分 → 候補を絞る → 接触判定 → 接触点をまとめる → 重なりと速度を解く(×8周) → 位置を進める → 止まった物は眠らせる | 地形(Heightmap)に球・箱・カプセルを降らせる動画(Day 47 の物理を Day 48 で撮影) | 1点で支えると箱は揺れ止まない。4点を同時に解く意味 |
| 16 | エフェクトとプレイアブルデモ | 48〜51 | 1フレームの全体図: 入力 → アニメ → 物理 → エフェクト → 描画 → 後処理 | 三人称で走り回る動画(Day 51) | 深度でフェードして、地面への「刺さり」を消すのがコツ |
| 17 | 仕上げ | 52〜56 | G-Buffer → 光の球を 1024 個描く → TAA(ずらす → 履歴と混ぜる) → 被写界深度 → モーションブラー | **ライブデモ(Day 56)** | 実機で動かす |

### 2-4. 発展(1枚)

18. 教養編(Day 57〜67)と VRM 編(Day 68〜73)をタイルで一覧。各1行
    - 教養編: コンピュートシェーダ、レイマーチング、CPU/GPU パストレーサ、Vulkan ハードウェア RT、ジオメトリ/テッセレーション/メッシュシェーダ、GPU 駆動と Hi-Z(Nanite 講読)、焼いたプローブ GI、Gaussian Splatting
    - VRM 編: MToon、表情、揺れもの、VRMA 再生、セルルックの仕上げ

### 2-5. まとめ(1枚)

19. **自分に合った教材は、作れる**
    - 条件(言語・レイヤ・順番・ペース・ゴール)を渡すと、その人専用のカリキュラムになる
    - スキルに確かめる手順まで書くと、85 Day 作っても品質が揃う
    - 途中で計画を変えてよい。教材が自分に合わせて育つ
    - 質疑へ
