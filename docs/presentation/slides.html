自分に合った教材が欲しかった

既存の教材とのずれ

  • 言語が C++ 前提(自分は C# メイン)
  • 「エンジンの使い方」か「低レイヤだけ」のどちらか
  • 順番が自分の興味と合わない(物理が無い、デモまで届かない)
  • まとまった時間を前提にしている

自分の条件

  • C# / .NET、ゲーム開発 20 年
  • なるべく低いレイヤから(GPU を使わない描画から)
  • 1 Day ずつ自分のペースで、毎回「動くもの」ができる
  • 最後は AAA 風のデモをキャラが走り回る
やったことこの条件を Claude Code に渡して、ロードマップ・計画書・答えのコードまで作らせた
「30日でできる!OS自作入門」の形式が好きで、あれのゲームエンジン版が欲しかった。でも自分の条件にぴったり合う本は無い。無いなら作ればいい。

教材の作り方 2/5

1 Day の教材の形

docs/plans/DayXX.html + reference/DayXX

計画書

  • 今日のゴール(動くもの1行)
  • 事前に読む資料
  • 理論の要点(図つき)
  • 前 Day からの差分・設計書
  • 完成条件(何が見えれば OK か)
  • 改造課題(理解の確認)

実験台

計画書の中で、その日の理論をブラウザで動かして確かめる部品

例: 箱の接触点が何点で支えるか、TAA の履歴の混ぜ方、パーティクルの寿命 …

答えのコード

前 Day の完全コピー+その日の差分。どの Day も単体で動く

写経しても、改造しても、読むだけでもいい。1 Day の差分は数百行(1〜3時間)に収める

ポイント「何を作るか」と「なぜそう動くか」と「答え」が、毎回そろって出てくる
使い方は人それぞれなので、写経の手順の話は省きます。自分は git diff --no-index で前日との差分を見ながら打っていますが、そこは本題ではない。
教材の作り方 3/5

実験台: 理論を動かして確かめる

Day 47 の計画書

計画書の中身(実物)

  • 文章 → 実験台 → 文章、の順に並ぶ
  • 実験台はつまみを動かすと、その場で結果が変わる
  • 物理・TAA・ラスタライザなどは、C# の実装を JS に移したものを複数の Day で共有
  • 外部ライブラリなし。ファイルを直接開けば動く

左の枠はスクロール・操作できます

ここで計画書を少しスクロールして見せる。最初は Markdown の計画書だったのを、途中で HTML に作り直して実験台を足した(後のスライドで)。
教材の作り方 4/5

Claude Code の仕掛け: create-day スキル

「Day 47 を作成して」の一言で、1 Day 分の教材ができるまで

ロードマップを読む→前 Day を確認→答えのコード→ 整形→ビルド→計画書→ 写経順の漏れを検算→HTML を検証→ロードマップにリンク

緑 = 確かめる工程

確かめる手順まで書く

AI に作らせていちばん怖いのは「それっぽいけど合っていない」。ビルド・検算・検証をスキルの手順に入れておく

失敗したら、手順を足す

写経する順番に漏れがあった → スキルに「コマンドで検算する」手順を追加。数字は「実測してから書く」も同じ

緑の工程が検証。毎回同じ手順で作らせるので、85 Day 作っても品質がそろう。失敗するたびに手順を足してきた。

  • 10月VRM 編を足したトゥーン調のアバターを、仕様どおりに描いてみたくなった

自作教材のいちばんの利点

理解度や興味が変わったら、教材のほうを変えられる

分からなければ説明を足す、重ければ分ける、作りたくなったら章を足す。本ではできない

ここが今日いちばん言いたいこと。計画を変えたら、後続の Day にも修正を波及させる。
